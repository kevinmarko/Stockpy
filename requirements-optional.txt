# Optional heavy forecasting dependencies — NOT installed by CI or the base
# `./setup.sh`. Install locally with `./setup.sh --optional` or
# `./.venv/bin/pip install -r requirements-optional.txt`.
#
# What this enables
# -----------------
# TensorFlow activates the hybrid CNN-LSTM forecaster in forecasting_engine.py
# (guarded by TENSORFLOW_AVAILABLE). Without it, run_cnn_lstm_forecast() returns
# zeros and CNN-LSTM silently contributes nothing to the multi-model ensemble
# blend or the inverse-RMSE skill tracker (forecasting/forecast_tracker.py) —
# exactly the graceful-degradation pattern Prophet uses. Everything else in the
# platform runs identically whether or not this file is installed.
#
# Why it is separate from requirements.txt
# ----------------------------------------
# TensorFlow is a ~500MB install and its CNN-LSTM path is a local, opt-in model.
# Keeping it out of requirements.txt keeps CI lean (CI installs requirements.txt
# only) and leaves the two TF-dormant tests fast.
#
# numpy safety (load-bearing — do not weaken)
# -------------------------------------------
# requirements.txt pins `numpy>=2.0,<2.3` (the <2.3 ceiling is enforced by
# numba==0.61.2 via pandas-ta/vectorbt). TensorFlow < 2.19 caps numpy below 2.2
# and would DOWNGRADE it, breaking numba's JIT paths. TF >= 2.19 accepts numpy
# 2.2.x, so the floor below keeps numpy exactly where requirements.txt wants it.
# Verified via `pip install --dry-run`: TF 2.21 leaves numpy 2.2.6 untouched and
# adds only net-new packages (keras, ml_dtypes, h5py, wrapt, …) — no downgrades.
#
# Platform note: on Apple Silicon macOS the plain `tensorflow` package ships
# native arm64 CPU wheels — do NOT use the deprecated `tensorflow-macos`, and
# `tensorflow-metal` (GPU) is unnecessary for this tiny model and adds version
# churn, so it is intentionally omitted.
tensorflow>=2.19

# CPU-only PyTorch — activates real local ProsusAI/FinBERT inference in
# signals/news_catalyst.py (see _get_finbert_pipeline / score_headlines)
# instead of the built-in keyword-lexicon fallback. requirements.txt already
# pins `transformers>=4.35.0`, but transformers needs a PyTorch OR
# TensorFlow backend to actually run a model -- without one, FinBERT
# silently falls back to the lexicon on every install, which is why this
# lives here rather than in requirements.txt. `torch>=2.0` is a broad,
# CPU-friendly floor (this repo has no CUDA/GPU requirement -- FinBERT is a
# small BERT-base model, CPU inference is fast enough for a batched,
# per-cycle headline-scoring workload); pip resolves the correct CPU wheel
# for the host platform automatically for a plain `torch` install (no
# `--index-url` / `+cpu` suffix needed on macOS or Linux x86_64/arm64).
# Everything else in the platform runs identically whether or not this file
# is installed -- see FINBERT_ENABLED / FINBERT_SCORE_CACHE_ENABLED in
# settings.py for the graceful-degradation contract.
#
# This same torch install ALSO now backs the BERT-LLA multi-horizon
# forecaster (forecasting/bert_lla.py, gated behind settings.
# BERT_LLA_ENABLED, default False) -- a second, independent consumer of
# this one dependency, not a reason to bump the floor; see
# forecasting/bert_lla.py's own TORCH_AVAILABLE guard for its graceful-
# degradation contract (falls back to the zero sentinel, same shape as
# the CNN-LSTM path without TensorFlow).
torch>=2.0

# faiss-cpu activates the embedded local vector store used by the RAG-Powered
# Portfolio Contextualizer (data/rag_index.py, gated behind
# settings.RAG_PORTFOLIO_CONTEXT_ENABLED, default False). It indexes the
# already-ingested sentiment corpus (sentiment_ingestion_audit) into a local
# faiss.IndexIDMap(IndexFlatIP) persisted to output/rag_index/index.faiss —
# a single-operator desktop app has no need for a server-mode vector DB
# (Qdrant/Docker); an embedded, in-process library is the right fit, matching
# this file's own tensorflow opt-in-heavy-dependency precedent. Without it,
# data/rag_index.py's DocumentVectorStore lazy-imports faiss inside every
# method and degrades to a graceful no-op (0 indexed / [] retrieved) exactly
# like the CNN-LSTM path above without tensorflow — the rest of the platform,
# including engine/portfolio_context.py's always-present deterministic
# sector-exposure summary, is unaffected either way.
faiss-cpu>=1.8.0

# pytrends activates the OPTIONAL, strictly-supplementary Google Trends
# overlay in data/attention_sources.py (gated behind settings.PYTRENDS_ENABLED,
# default False), used only as a fallback when the primary Wikipedia-
# pageviews attention feature (settings.WIKIPEDIA_ATTENTION_ENABLED) yields
# nothing for a symbol. This package is intentionally kept OUT of
# requirements.txt: its upstream repo (GeneralMills/pytrends) was archived
# read-only in April 2025 (no further maintenance, ever) and it scrapes an
# undocumented, unstable Google endpoint that is well known to return
# frequent HTTP 429s even under light, single-operator use -- matching this
# file's own tensorflow/torch/faiss-cpu precedent of keeping a fragile or
# heavy opt-in dependency out of the pinned, CI-installed requirements.
# Without it, data/attention_sources.py's `_fetch_pytrends_attention_score()`
# lazily imports pytrends inside the function body and degrades to a
# graceful no-op (returns None, never raises) exactly like the CNN-LSTM/RAG
# paths above without their optional dependency -- the primary Wikipedia
# path is completely unaffected either way, and is never blocked on this
# package being installed.
pytrends>=4.9.2

# sentence-transformers activates the local SBERT embedder for the semantic
# Related Sector Selection feature (data/sector_embeddings.py, gated behind
# settings.SECTOR_SELECTION_ENABLED, default False, plus
# settings.SECTOR_SIMILARITY_EMBEDDER="sbert", the default embedder choice).
# It sits on top of `torch>=2.0` (already above, for FinBERT) and
# `transformers>=4.35.0` (already in requirements.txt) -- the marginal
# dependency cost of adding this package is small, not a new heavy runtime.
# Kept out of requirements.txt for the same reason as the other entries in
# this file: it is a local, opt-in model, and CI should stay lean. Without
# it, data/sector_embeddings.py's SBERT_AVAILABLE guard is False and every
# cosine_similarity computed by sector_selection_engine.py degrades to NaN,
# never a fabricated value (CONSTRAINT #4) -- exactly like the CNN-LSTM/
# FinBERT/RAG paths above without their own optional dependency.
sentence-transformers>=2.2

# playwright powers browser_diagnostics.py's real headless-Chromium captures
# (console/page errors, Core Web Vitals, DOM node count, screenshots) for the
# DevTools widget tools in investyo_mcp_server.py (inspect_webapp_screen,
# audit_webapp_vitals, compare_screen_snapshots). After installing this package
# you must ALSO download its Chromium binary:
#   ./.venv/bin/playwright install chromium
# (a separate ~180MB download this pip install alone does not perform). Kept
# out of requirements.txt for the same reason as every other entry in this
# file: it is a heavy (~40MB package + ~180MB browser), opt-in, local-only
# capability, and CI should stay lean. Without it (or with the browser not
# installed), browser_diagnostics.py's lazy `import playwright` degrades to a
# graceful `{"available": False, "reason": ...}` -- never raises, never a
# fabricated screenshot/vitals value (CONSTRAINT #4/#6) -- exactly like the
# CNN-LSTM/FinBERT/RAG/pytrends paths above without their own optional
# dependency, and the three MCP tools above fall back to their existing
# HTTP-reachability-only behavior. Also gated by settings.BROWSER_DIAGNOSTICS_ENABLED
# (default False) -- installing the package alone does not turn this on.
playwright>=1.40

# sentry-sdk activates the Sentry error tracking integration for unattended
# background daemons. Kept out of requirements.txt to preserve CI leanness
# since it's only needed for live, deployed usage. Without it, the
# observability/sentry_integration.py file falls back gracefully, logs a
# WARNING, and the daemon proceeds with startup -- the exact same degradation
# pattern used for the machine learning modules above.
sentry-sdk>=2.0.0
