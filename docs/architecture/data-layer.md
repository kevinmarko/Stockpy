# Architecture: Data Layer & Persistence

> Part of the split-out `CLAUDE.md` System Architecture reference. See [../../CLAUDE.md](../../CLAUDE.md) for the index.

- **config.py** — Single Source of Truth (SSOT). `COLUMN_SCHEMA` defines every column's Google Sheets header, internal dict key, and display format, plus Pandera schemas for validation. Any new field must be added here first before use elsewhere.
- **dto_models.py** — `MarketBarDTO`, `FundamentalDataDTO`, `MacroEconomicDTO`, `RobinhoodPositionDTO`. All market/fundamental/macro data flowing through calculation layers must be coerced into these DTOs — raw dict lookups or positional indexing in calc code is not allowed. DTO parsers also handle messy upstream strings (currency symbols, `%`, `"N/A"`, padding). `FundamentalDataDTO` carries a `current_ratio` field (`__init__` default `NaN`; `from_raw_dict` reads `info.get("currentRatio", NaN)`) — `currentRatio` is already emitted by `data/yahoo_fundamentals.py` and is now carried through the DTO and surfaced by `engine/advisory.py` as `key_indicators["current_ratio"]`. `MacroEconomicDTO` now accepts an optional `hmm_risk_on_probability: Optional[float] = None` (the `regime/hmm_regime.py` second opinion). `None` (the default) reproduces the exact pre-HMM behavior. The rules-based `_rules_based_regime` stays primary; `market_regime` downgrades RISK ON → NEUTRAL (logged) when `hmm_risk_on_probability < HMM_RISK_ON_DOWNGRADE_THRESHOLD` (0.3) — it can never independently declare a worse regime or upgrade a better one. `killSwitch` ORs in a lowered-threshold check (`vix > KILLSWITCH_VIX_THRESHOLD_AGREED`=25 or `sahm_rule_indicator >= KILLSWITCH_SAHM_THRESHOLD_AGREED`=0.3, vs. the base 30/0.5) only when the rules-based regime is RECESSION AND the HMM agrees (`1 - hmm_risk_on_probability > HMM_RISK_OFF_AGREEMENT_THRESHOLD`=0.7) — strictly OR'd with the base condition, never less sensitive.
- **data_engine.py** — `DataEngine` (live Yahoo Finance/FRED via `fredapi`) and `MockDataEngine` (test fixture), both implementing an `IDataProvider` interface. Fetching is strictly decoupled from calculation. `IDataProvider` now also declares `fetch_macro_history() -> pd.DataFrame` (full historical VIX/yield-curve series for `regime/hmm_regime.py`'s expanding-window fit, distinct from `fetch_macro_raw()`'s single current-snapshot dict). `DataEngine.fetch_macro_history()` pulls full unbounded series via `self.fred.get_series('VIXCLS'/'T10Y2Y')`; returns an empty DataFrame (never fabricated rows) if FRED is unavailable. `MockDataEngine.fetch_macro_history()` returns a deterministic 500-row synthetic series (seeded) for offline tests. **Parallel fetch (2026-07):** `DataEngine.fetch_technical_raw()`/`fetch_fundamentals_raw()` were serial `for symbol in tickers:` loops making one blocking yfinance HTTP call at a time; both now route through a `ThreadPoolExecutor` sized by `settings.DATA_FETCH_MAX_CONCURRENCY` (default 8, matching the `FORECAST_MAX_CONCURRENCY`/`ADVISORY_MAX_CONCURRENCY` convention), collapsing wall-clock fetch time from ~N sequential round-trips to ~N/workers. Per-ticker try/except is preserved (one bad symbol still can't abort the batch); the old `sleep(0.1)`-every-5-tickers throttle in `fetch_fundamentals_raw` was dropped in favor of the bounded worker count as the de-facto rate limit. Set `DATA_FETCH_MAX_CONCURRENCY=1` to force the original sequential path. **New env var:** `DATA_FETCH_MAX_CONCURRENCY`. **`fetch_technical_raw_cached()` — HistoricalStore routing for `main_orchestrator.py` (2026-07):** `main_orchestrator.py`'s `fetch_all_data_async()` was the last major tech-bars call site that bypassed `HistoricalStore` entirely — it called `DataEngine.fetch_technical_raw()` directly every cycle for the full ticker universe (unlike `main.py`'s `_fetch_bars_for_universe()`, which already routes through `HistoricalStore.get_bars()`). `DataEngine.fetch_technical_raw_cached(tickers)` closes this gap: a new, additive method (alongside, not replacing, `fetch_technical_raw()`) that lazily imports `data.historical_store.HistoricalStore` and `data.market_data.get_provider()` (this repo's `HistoricalStore`-lazy-import convention, matching `processing_engine.py`/`macro_engine.py`) and routes each ticker through `HistoricalStore.get_bars(symbol, lookback_days=settings.BARS_BACKFILL_DAYS, provider=<CompositeProvider singleton>)` instead of a fresh `yf.Ticker(symbol).history(period="2y")` call — a symbol whose bars are already persisted needs only its `(last_date, today]` delta fetched. Preserves the exact `ThreadPoolExecutor`/`DATA_FETCH_MAX_CONCURRENCY` concurrency pattern and per-ticker try/except dead-letter resilience of `fetch_technical_raw()`. Falls through to calling `fetch_technical_raw(tickers)` verbatim (byte-identical output) when `settings.HISTORICAL_STORE_ENABLED` is `False`, or when `HistoricalStore`/`get_provider()` construction raises — CONSTRAINT #6, this can only ever remove a redundant refetch, never silently substitute bad data. `MockDataEngine` gained a matching `fetch_technical_raw_cached()` that is a plain alias for its own `fetch_technical_raw()` (mock data is synthesized fresh from `datetime.now()` on every call, so there is no real per-ticker fetch to cache against a DB; this also keeps `main_orchestrator.py`'s existing `MockDataEngine()` offline-fallback branches — no `credentials.json`, or a live-fetch coming back empty — working unchanged now that the call site is unconditional). `fetch_technical_raw()` itself is unchanged.
- **data/market_data.py** — Swappable market-data layer with a provider abstraction (`MarketDataProvider` ABC) that hides the concrete backend from all signal, indicator, and forecasting code. **Provider auto-selection** (evaluated at `CompositeProvider` construction): (1) `MARKET_DATA_PROVIDER=alpaca` or Alpaca keys present → `AlpacaProvider` (real-time IEX via alpaca-py); (2) otherwise → `YFinanceProvider` (zero config, ~15-min delayed, `is_stale=True` always). **Components**: `Quote` (frozen dataclass: symbol, price, bid, ask, UTC timestamp, is_stale, source); `MarketDataError` (typed exception — orchestrator catches per-symbol for dead-letter resilience); `AlpacaProvider` (`StockHistoricalDataClient` + `StockLatestQuoteRequest` + `StockBarsRequest`, IEX feed, stale if quote age > `stale_threshold_seconds`=60); `YFinanceProvider` (`Ticker.fast_info` for quotes, `Ticker.history()` for bars — always `is_stale=True`, wraps yfinance errors as `MarketDataError`; ALSO the fundamentals fallback, returning raw `Ticker.info` when the primary Yahoo-computed engine yields nothing); `YahooFundamentalsProvider` (`SOURCE="yahoo_computed"` — the **PRIMARY fundamentals source**; pulls Yahoo's FREE financial statements — `income_stmt`, `balance_sheet`, `cashflow`, `dividends`, `institutional_holders` — plus price/shares, then delegates to the pure `data/yahoo_fundamentals.py::compute_fundamentals(...)` to derive 15 equity fundamentals as a yfinance `.info`-style dict so `FundamentalDataDTO.from_raw_dict()` is unchanged; NaN-degrading per CONSTRAINT #4 — missing input → NaN, never a fabricated 0.0; caches SPY returns for the beta computation); `FinnhubProvider` (**DEPRECATED as a fundamentals source and UNWIRED from `CompositeProvider`** — the class is retained but no longer consulted for fundamentals; `FINNHUB_API_KEY` is now used ONLY by `signals/news_catalyst.py` for company news / earnings); `CompositeProvider` (routes quotes/bars to the selected backend, fundamentals to **`YahooFundamentalsProvider` (primary) → yfinance `.info` (emergency fallback)** — Finnhub is no longer in the fundamentals path; exposes a `source_name` property reporting the active fundamentals backend; in-process TTL quote cache, logs startup banner once). **Options Data**: `OptionsDataProvider` ABC hides the concrete chain source. `YFinanceOptionsProvider` fetches the raw chain (strikes, bids, asks, IV) from `yfinance`. `CompositeOptionsProvider` wraps it, injecting the spot price from the primary `MarketDataProvider` (e.g. FMP) so that Black-Scholes Greeks calculations have an accurate underlying price. **Bar shape contract**: `get_intraday_bars()` returns a DataFrame with columns `Open, High, Low, Close, Volume` and a timezone-naive `DatetimeIndex` sorted ascending — identical to `DataEngine.fetch_technical_raw()`'s shape so all processing/forecasting/strategy code runs unchanged. **Quote cache**: in-process dict + monotonic TTL (default `MARKET_DATA_QUOTE_TTL_SECONDS`=30 s), never written to disk. **Bars cache (2026-07, PR A hot-path)**: `CompositeProvider.get_intraday_bars()` also carries an in-process `_BarsCache` (thread-safe `threading.Lock`, keyed `(symbol, lookback_days)` → `(df, monotonic-expiry)`, default `MARKET_DATA_BARS_TTL_SECONDS`=300 s, returns a defensive `df.copy()` so callers can't poison the cache) so the "bars fetched twice per symbol" pattern (universe pre-fetch + advisory-overlay refetch) collapses to one backend pull within the TTL — bars are daily-resolution so a few-minutes TTL is safe. `invalidate_bars(symbol, lookback_days)` / `clear_bars_cache()` force a refresh. **Two SCALE-CRITICAL emission rules (do NOT "fix" — downstream depends on them)**: `dividendYield` is emitted as a **FRACTION** (e.g. `0.0257`, not `2.57`) — it is NOT routed through `normalize_yfinance_dividend_yield` and is consumed as-is; `debtToEquity` is emitted as a **PERCENT** (`×100` → e.g. `150.0`, not `1.5`) because two downstream consumers divide by 100. Plain-fraction ratios (`returnOnEquity`, `grossMargins`, `operatingMargins`, `payoutRatio`) are unscaled; `payoutRatio` uses `abs()` of the (negative) "Cash Dividends Paid" cash-flow line. **Beta** = `Cov(stock, SPY) / Var(SPY)` over `BETA_LOOKBACK_DAYS` (default 504) of daily returns, with the SPY return series cached inside the provider. **Fundamentals cache**: `CompositeProvider` carries an in-process `_FundamentalsCache` (default `FUNDAMENTALS_CACHE_TTL_SECONDS`=21600 s / 6 h) that caches positive AND empty (negative) responses so coverage-miss symbols never re-hit the network within the TTL window. **Finnhub 429 machinery (retained but dormant for fundamentals)**: the deprecated `FinnhubProvider` still wraps outbound calls in a `_SlidingWindowRateLimiter` (default `FINNHUB_RATE_LIMIT_PER_MIN`=50) with one-shot exponential backoff + 429 retry — relevant now only if a caller invokes it directly, since it is no longer on the fundamentals path. `clear_fundamentals_cache()` purges the cache for forced refresh. Module-level singleton via `get_provider()` / `reset_provider()`. **New env vars**: `MARKET_DATA_PROVIDER`, `FUNDAMENTALS_SOURCE` (`"yahoo"` default | `"yfinance_info"`), `BETA_LOOKBACK_DAYS`, `FINNHUB_API_KEY` (now `news_catalyst`-only, NOT a fundamentals dependency), `MARKET_DATA_QUOTE_TTL_SECONDS`, `MARKET_DATA_BARS_TTL_SECONDS` (bars-cache TTL, default 300 s, GUI-writable non-secret allowlist key), `FUNDAMENTALS_CACHE_TTL_SECONDS`, `FUNDAMENTALS_NEG_CACHE_TTL_SECONDS` (int, default 900 — separate, shorter TTL for the empty/negative-response cache case, previously undocumented), `FINNHUB_RATE_LIMIT_PER_MIN`. **`os.environ`→`settings.X` fix (2026-07-31):** `CompositeProvider.__init__`, `_select_quote_provider`, `get_intraday_bars`, `get_fundamentals`, and `YahooFundamentalsProvider._beta_period` all read the above config values via `os.environ.get(...)` instead of `settings.settings.X` — silently ignoring any value set only in `.env` — the 3rd instance of this exact bug class after `signals/news_catalyst.py::build_finnhub_client` and `prompt_registry/registry.py` (see `CLAUDE.md`'s `settings.X`/`os.environ` convention bullet). All five call sites now read `settings.settings.X`.
- **api/data_api.py** — Public interface for platform data ingestion and analytics.
  - `GET /data/metrics/performance/{symbol}`: fetches technical metrics and trailing performance.
  - `GET /data/options/chain/{symbol}`: fetches real-time options chains (strikes, bid/ask, last, IV) for a given symbol and expiration via `DataEngine`, and computes Greeks (Delta, Gamma, Theta, Vega, Rho) dynamically using `technical_options_engine.py`'s `OptionsPricingRecommender.black_scholes_pricing_and_greeks`. Designed for the Options Chain webapp interface.
  - `GET /data/technicals/screener`: technical screener using composite score sorting.
- **The FMP data layer** (`data/fmp_client.py` + `data/fmp_fundamentals.py` + `data/fmp_macro.py` + `data/fmp_feeds_company.py` + `data/fmp_feeds_market.py` + a new `FMPProvider` class co-located in `data/market_data.py`, 2026-07, Financial Modeling Prep integration — full operator reference: [`docs/FMP_INTEGRATION.md`](../FMP_INTEGRATION.md)) — `data/fmp_client.py` is the single shared HTTP seam every FMP consumer goes through (base URL, `settings.FMP_API_KEY`, throttle/retry/breaker in `_fmp_get`, `FMPUnavailable`, `reset_fmp_rate_limiter()`, `get_fmp_call_stats()`, thin per-endpoint wrappers returning raw parsed JSON — no pandas, no key-mapping, no unit math) because the FMP rate limit is **per-ACCOUNT, not per-concern**: seven consumers (fundamentals, quotes/bars, analyst, earnings, macro/calendar, insider/sector, options context/peers) share one 300 req/min Starter budget, and a per-consumer limiter would blow it by construction — the same reasoning that keeps one module-level GDELT limiter in `data/sentiment_sources.py` and makes `data/etf_holdings.py` reuse `edgar_fundamentals._throttle` instead of opening a second SEC client. **Module list**: `data/fmp_fundamentals.py` is pure and I/O-free (`map_fundamentals(...) -> Dict[str, Any]` — every scale conversion and NaN decision, mirroring `data/yahoo_fundamentals.py`'s template so scales are unit-testable with zero mocking) and feeds the `FMPProvider` class (the `MarketDataProvider` ABC impl, a pure I/O shell delegating all math to `fmp_fundamentals`, `SOURCE="fmp"`); `data/fmp_macro.py` shapes treasury rates + `settings.FMP_ECON_INDICATORS` as FRED-compatible `(series_id, date, value)` rows written into the EXISTING `macro_history` table (`year10 - year2` → `T10Y2Y`, `unemploymentRate` → `UNRATE`, `source='fmp'`) rather than a new table, so `get_macro`/`calculate_sahm_rule`/`compute_hmm_risk_on_probability` work unchanged — FMP **supplements** FRED and cannot replace it (no Starter equivalent for `VIXCLS` or `BAMLH0A0HYM2`/HY OAS); `data/fmp_feeds_company.py` (per-symbol analyst consensus/grades + earnings calendar/surprises, cadence-gated 24h/12h) and `data/fmp_feeds_market.py` (per-cycle insider-trading statistics + dated sector PE/performance snapshots + economics calendar events via `fetch_economics_calendar`) populate `pipeline/production_steps.py`'s `_apply_fmp_analyst`/`_apply_fmp_earnings`/`_apply_fmp_insider`/`_apply_fmp_sector`/`_apply_fmp_econ_calendar` — five NaN-fill-first, gate-checked, lazy-import, shared-cycle-deadline-guarded (`_fmp_deadline`), `except Exception`-degrading stubs built on the `_apply_sector_heat_factor` template and called from `StrategyEvalStep.run`; all five feeds are **diagnostic-only, never a `SignalModule`, never a `SIGNAL_WEIGHTS` entry** — none has point-in-time history on day one (FMP serves only the CURRENT analyst consensus; insider quarterly aggregates keep changing as Form 4s land), so nothing new ever enters `dto_models.py`, `signals/`, or the perturbation/lookahead harness — "a signal the repo cannot backtest cannot earn a weight" is also the no-lookahead guarantee mechanism, not just a policy. New `config.COLUMN_SCHEMA` columns: `Analyst_Target_Consensus`/`Analyst_Target_Upside`/`Analyst_Grade_Score`, `Days_To_Earnings`/`Last_EPS_Surprise_Pct` (the EXISTING `Earnings_Date` column gains FMP as a SECOND source alongside Finnhub, unlike Finnhub not limited to a 30-day forward window), `Insider_Buy_Sell_Ratio`, `Sector_PE`/`Sector_1D_Change`, `Next_Macro_Event`/`Next_Macro_Event_Date`. New `data/historical_store.py` tables: `analyst_history` (forward-archive-only, PK `(symbol, as_of)`), `earnings_events` (PK `(symbol, event_date)`, future-dated rows with NULL actuals are normal and NOT lookahead — only the RESULT is; a row counts as "actual" iff `eps_actual IS NOT NULL`, a trailing surprise requires `event_date <= as_of` AND a non-null actual, `last_updated` is persisted verbatim as an imperfect, explicitly-not-a-guarantee PIT defense), `insider_stats` (PK `(symbol, year, quarter)`, consumers must apply `settings.FMP_INSIDER_MIN_LAG_DAYS`=45 — a quarter's aggregate keeps changing as late Form 4s land, and 45 is a conservative judgment call, not a derived constant), `sector_snapshots` (PK `(sector, date)`, the one feed with a genuine PIT story since both source endpoints are date-parameterized — consumers must always use the dated form). **Fallback chain**: built once per `CompositeProvider.__init__`, gated by `settings.FMP_FALLBACK_ENABLED` (default `True`; `False` collapses each chain to `[primary]` so a failure propagates exactly as today) — quotes/bars: FMP → Alpaca (if keyed) → yfinance; fundamentals: FMP → `YahooFundamentalsProvider` → yfinance `.info`. Two-tier resilience: per-call chain fallback (Tier 1) plus `fmp_client`'s own cooldown breaker (Tier 2, `_gdelt_get`'s design verbatim) so an outage costs one round of failures then skips to fallback at zero network cost for the cooldown window, self-expiring rather than a per-process latch. **A silent fallback that looks like success is the specific failure mode this design defends against**, via four mechanisms: `Quote.source` (unchanged, already per-quote truth); a thread-safe `_source` key embedded in the fundamentals dict, which `data/historical_store.py::_source_name(provider, raw)` already prefers over the provider object's own label (landed in wave 0 — a per-response key matters because `data_engine.py` calls this under an 8-thread pool) making `SELECT source, COUNT(*) FROM fundamentals_history WHERE as_of = DATE('now') GROUP BY 1` the ground-truth operator query; module-level `_PROVIDER_SERVE_COUNTS` keyed `(kind, source)` plus `get_provider_serve_counts()`/`reset_provider_serve_counts()` (wave-1, F1); and a `WARNING` (never DEBUG/INFO) on every fallback naming provider, symbol, and exception. Bars have no per-row source field — `_upsert_bars` stamps a provider-level name only, a documented limitation relying on the serve-count + WARNING mechanisms rather than per-row attribution. **Starter-tier entitlement boundary, structural not conventional**: `_fmp_get`'s status-code matrix treats a 403 or an `ACCESS DENIED`-shaped 200 body as neither retryable nor breaker-advancing — it latches that ENDPOINT PATH dead for the rest of the process (a plan entitlement does not change mid-run) and logs one ERROR per endpoint, so an Ultimate-only call costs exactly one wasted request per process, not one per symbol per cycle. This is the exact mechanism `Institutional Velocity` degrades through, and it stays **permanently hardcoded `0.0`, not fixable by this integration**: Form 13F (institutional ownership) is Ultimate-only and Starter has no short-interest feed either, so no FMP endpoint on this account can fill either half of that calculation; `data/etf_holdings.py`'s SEC N-PORT path and its 1–5 month staleness are likewise untouched. **Rate-limit budget** (the plan's own math): Starter publishes 300 req/min; the client targets a conservative ceiling of 240 (80%) via `settings.FMP_MIN_REQUEST_INTERVAL_SECONDS` (default 0.25s, minimum-spacing not sliding-window, lock held ACROSS the sleep — the `edgar_fundamentals._throttle` pattern, deliberately NOT `_SlidingWindowRateLimiter`, whose "thread-unsafe by design, the orchestrator's per-symbol loop is serial" docstring claim is now false once `data_engine.py` runs `get_fundamentals` under an 8-thread pool). Naive cost for a 33-symbol universe is ~9 calls/symbol = 299/cycle, a coin flip against the ceiling; three reductions bring steady state to ≈100 req/cycle (cold-cache worst case ≈267): `batch-quote` folds 33 quote calls into 1; cadence gating (analyst 24h, earnings 12h, insider 7d) costs 33 requests on a refresh cycle and zero otherwise; `/profile` is cached at `FUNDAMENTALS_CACHE_TTL_SECONDS` (6h), amortizing another 33. Honest cost: ≈100 requests × 0.25s ≈ 25s of SERIALIZED issuance per cycle — FMP turns N parallel yfinance calls into N serialized FMP calls, so `DATA_FETCH_MAX_CONCURRENCY` buys nothing on this path; `settings.FMP_MAX_SECONDS_PER_CYCLE` (default 120.0, the `ETF_HOLDINGS_MAX_SECONDS_PER_CYCLE` precedent) is the guard, degrading remaining symbols to `NaN` once spent rather than overrunning the cycle. Shared deadline optimization passes `time.monotonic() + FMP_MAX_SECONDS_PER_CYCLE` down into per-symbol loops (`_apply_fmp_analyst`, `_apply_fmp_earnings`, `_apply_fmp_insider`), guaranteeing the 120s budget is shared across all three loops combined rather than resetting per feed. **Bars adjustment convention is the single highest silent-corruption risk in this integration**: `YFinanceProvider.get_intraday_bars` calls `Ticker.history(auto_adjust=True)` — split AND dividend adjusted — while FMP's `/historical-price-eod/light` and `/full` variants are SPLIT-ONLY; `full` is the obvious-looking choice and it is wrong. `settings.FMP_BARS_ADJUSTMENT` defaults to `"dividend-adjusted"`, and `scripts/verify_fmp_bars.py` (agent F5, network-marked, NOT part of the pytest suite — a manual operator gate) is a HARD GATE: it must exist and PASS (max abs relative close diff `< 1e-4` across KO/JNJ/AAPL over 2 years) before `FMP_BARS_ADJUSTMENT` is ever set to anything else, or before `FMP_BARS_ENABLED` is ever flipped on live. Second-order risk the script cannot catch: `price_bars` has a `(symbol, date)` PK, so changing bars source on an EXISTING database splices two adjustment conventions into one series at the cutover date — delete `price_bars` and re-backfill instead; no test catches this. **Provider & capability defaults**: `MARKET_DATA_PROVIDER="fmp"`, `FUNDAMENTALS_SOURCE="fmp"`, and 14 `FMP_*_ENABLED` flags + `FMP_QUOTES_REALTIME` default to `True` per operator decision for active FMP deployment. **Verification honesty**: every FMP field name, response shape, and unit claim here (the fundamentals scale-conversion table, the bars adjustment-variant behavior, the entitlement boundary) originates from live probes run via the FMP MCP connector against a real Starter account during planning, and, for the bars variants specifically, re-probed live against AAPL during this doc-and-script pass (`dividend-adjusted`/`non-split-adjusted` return `adjClose`, `full` returns `close`, `light` returns `price`-only — a genuine field-name divergence `scripts/verify_fmp_bars.py::_extract_close` handles defensively) — but the CONSUMER MODULES themselves were built and unit-tested entirely OFFLINE against those probed shapes, with no live re-verification of the shipped implementation, since this sandbox has no live-market network access on its normal dev/CI path. Treat every scale/unit claim as probe-informed, not implementation-verified, until an operator runs the manual eyeball gates in `docs/FMP_INTEGRATION.md` §4 against a live account.

When enabled, `EdgarSource._fetch_fulltext()` calls SEC's full-text search index at `https://efts.sec.gov/LATEST/search-index` (path casing matters — lowercase `/latest/` 404s), filtered by `settings.EDGAR_FULLTEXT_FORMS` (comma-separated, default `"8-K,10-K,10-Q"`, mirroring the `SENTIMENT_SOURCES` fan-out convention), the ticker's CIK (reusing the existing `_lookup_cik` cache), and a `since`-derived date range. Matched **10-K/10-Q** filings have their primary document fetched and converted to plain text (`_extract_filing_text` — a best-effort `Item 1A`/`Item 7` Risk-Factors/MD&A regex narrows the text when those markers are cleanly present, but always falls back to the filing's FULL text rather than risk silently dropping content — a documented, deliberate accuracy/robustness tradeoff, not a bug), then split into ≤`settings.EDGAR_FULLTEXT_CHUNK_TOKENS` (default 512, matching FinBERT's context window) whitespace-token chunks via `_chunk_text`. Matched filings of other configured form types (e.g. 8-K, when included in `EDGAR_FULLTEXT_FORMS`) are represented by a short entity/form headline-style string rather than a body fetch, since the always-on 8-K path above already covers 8-K headline text. Every chunk/headline-string from one `fetch()` call is scored TOGETHER via `signals/news_catalyst.py::score_headlines()` — PR417's batched entry point — rather than one call per chunk. **Leakage-safe timestamping**: every resulting document's `as_of` is derived from EFTS's own official `file_date` response field (never wall-clock fetch time), so a filing can never be attributed to the wrong trading day regardless of when the ingestion process happened to run — proved by a dedicated test in `tests/test_sentiment_sources.py::TestEdgarFullTextSearch` mirroring `tests/test_sentiment_pit_lookahead.py`'s style. **Shared SEC rate-limit throttle**: `_efts_search`/`_fetch_filing_text` reuse `data/edgar_fundamentals.py`'s exact `_throttle()` (monotonic-clock sliding gap held across a lock, ~10 req/s) rather than a second, independent throttle, so this module's EDGAR full-text traffic shares the same process-wide SEC fair-access budget as the fundamentals backfill instead of each independently assuming it owns the full 10 req/s. Every failure (EFTS network/HTTP error, malformed JSON, a filing whose body text can't be fetched, a throttle/import error) degrades to skipping just that piece of work — never raises, never discards the always-on 8-K docs a `fetch()` call already collected (CONSTRAINT #6). **New env vars**: `EDGAR_FULLTEXT_ENABLED` (bool, default `False`), `EDGAR_FULLTEXT_FORMS` (str, default `"8-K,10-K,10-Q"`), `EDGAR_FULLTEXT_CHUNK_TOKENS` (int, default `512`) — all three added by the settings-scaffolding PR (#416) and wired by this extension. **Historical backfill (2026-07):** `GDELTSource.fetch()` was rewritten from a single "50 most recent articles" call (which would have silently returned only today's newest headlines for any backfill request, never genuine history) to `_MAX_WINDOWS`-bounded `_CHUNK_DAYS`-wide `startdatetime`/`enddatetime`-scoped windowed queries, so a `since` far in the past (e.g. a 5-month backfill) actually walks real historical windows; a live per-cycle call with a recent `since` still resolves in exactly one window/request. `RedditSource.fetch()` similarly moved off a hardcoded `t=day` to `_time_bucket_for(since)` (the narrowest Reddit `t=` bucket — hour/day/week/month/year/all — that still covers `since`) plus `after`-cursor pagination bounded by `REDDIT_BACKFILL_MAX_PAGES`, stopping as soon as a page's oldest post predates `since` (Reddit returns `sort=new`, so everything past that point is even older). GDELT/EDGAR/Finnhub are genuinely, honestly backfillable with **zero credibility bias** (institutional sources are policy-trusted at `1.0` regardless of when they're scored); Reddit backfill is real but carries a documented caveat — a backfilled post's `S_authority` reflects the author's CURRENT account state, not their state at post time, since Reddit's API has no way to answer that (see `RedditSource`'s docstring). Yahoo RSS has no historical archive at all (a live feed only) and cannot backfill under any settings. `HistoricalStore.get_sentiment_archive_depth_by_source()` (grouped `MIN`/`MAX`/`COUNT` SQL aggregation, read-only) reports per-source archive depth so a future validation gate can weigh institutional depth separately from Reddit's rather than one blended `SENTIMENT_PIT_MIN_MONTHS` number that would overstate confidence in the weaker component. See `scripts/backfill_sentiment_history.py` in `docs/architecture/webapp-and-gui.md` for the operator-facing CLI. **Shared GDELT rate limiter (2026-07):** both GDELT consumers in this module -- `GDELTSource` (`mode=artlist`, per-symbol tone documents) and `GDELTVolumeSource` (`mode=timelinevol`, per-sector article counts) -- now issue every request through ONE module-level limiter (`_gdelt_get`), for the same reason `data/etf_holdings.py` is required to reuse `data/edgar_fundamentals.py`'s `_throttle` rather than open a second SEC client: the courtesy budget is per-HOST, so two independently unthrottled clients in one process is exactly how a 429 storm starts. **The failure it fixes:** `GDELTSource.fetch()`'s windowed backfill (above) is one request for a live per-cycle `since` and so never revealed a problem, but a real `scripts/backfill_sentiment_history.py --months 6` run is ~26 unspaced requests PER SYMBOL -- measured against a 33-symbol universe on 2026-07-29, GDELT answered HTTP 429 to substantially every one, so the backfill burned wall-clock and archived nothing while logging one warning per window. Three bounds, not one: (1) **minimum spacing** between request issuance (`settings.GDELT_MIN_REQUEST_INTERVAL_SECONDS`, default 5.0s), lock held across the sleep for the same serialization reason documented on `edgar_fundamentals._throttle`; (2) **retry with exponential backoff** on 429/5xx (`GDELT_MAX_RETRIES` default 2, `GDELT_RETRY_BACKOFF_SECONDS` default 5.0), preferring a parseable `Retry-After` header over the computed wait; (3) a **cooldown circuit breaker** -- after `GDELT_COOLDOWN_THRESHOLD` (default 3) CONSECUTIVE FAILED requests (429, 5xx, or transport error alike), GDELT calls are SKIPPED outright (no sleep, no request) for `GDELT_COOLDOWN_SECONDS` (default 300), which is what stops an unresponsive host from turning a long backfill into hours of certain-to-fail requests while EDGAR/Finnhub/Reddit starve for the cycle's wall-clock budget. **Counting transport errors was a mid-change correction, not the original design:** the first cut counted 429s only, and a live re-test minutes later found GDELT had stopped 429-ing this host and started READ-TIMING-OUT instead -- one 6-month symbol still cost 262 s to archive zero documents (26 windows x a 10 s timeout), the exact pathology the fix existed to remove. From the caller's side "refusing us" and "not answering us" have identical cost and identical remedy; requiring CONSECUTIVE failures (one success resets the count and clears any open cooldown) is what keeps a single flaky socket from opening it. RETRIES stay 429/5xx-only, though: an immediate retry of a read timeout just times out again at full cost, and a 404 is a bad query rather than an overloaded host. Re-measured live after the correction: 262 s -> 30.3 s for the same symbol, with later symbols skipping instantly while the cooldown is open. `GDELTSource.fetch()` treats `GDELTUnavailable` (and only that) as a signal to ABANDON the remaining windows of the range -- every other per-window failure keeps the pre-existing skip-and-continue behaviour -- and a partial range is the honest outcome, logged with the count of windows that completed. **New `SentimentSource.deadline` seam:** `CompositeSentimentSource` checks its wall-clock budget BETWEEN sources, which is sufficient only while every source is one request; it now also assigns `source.deadline = self._cycle_deadline` before each `fetch`, and `GDELTSource` consults `deadline_exceeded()` between windows so the throttle's sleeps cannot overrun the budget from inside a single call. Single-request sources correctly ignore it. **Behaviour-change honesty note:** unlike most flags in this codebase these defaults are NOT a no-op -- a live cycle now covers fewer symbols' GDELT documents per pass than an unthrottled (and largely 429-ing) one attempted to, and GDELT publishes no hard rate-limit number so 5.0s/2/300s are a conservative choice, not a documented contract. `GDELT_MIN_REQUEST_INTERVAL_SECONDS=0` with `GDELT_MAX_RETRIES=0` and `GDELT_COOLDOWN_THRESHOLD=0` reproduces the pre-limiter behaviour exactly. Tests: `tests/test_gdelt_rate_limiter.py` (fake clock, no real sleeps); the root `conftest.py` zeroes the interval suite-wide and resets the module-level limiter state around every test so an open cooldown cannot leak between tests. **Finnhub silently contributed nothing, fixed 2026-07:** `FinnhubSentimentSource.fetch()` goes through `signals/news_catalyst.py::build_finnhub_client()`, which read the key via `os.environ.get("FINNHUB_API_KEY", "")` -- unlike every other credential-gated source in THIS SAME FILE (`RedditSource`/`EdgarSource`, both correctly read `settings.REDDIT_CLIENT_ID`/`settings.EDGAR_USER_AGENT`). Pydantic-settings' `env_file=".env"` loads a value from `.env` into the `Settings` model directly; it does not also copy it into the process's real `os.environ`. An operator whose only source for this key is `.env` (the documented, normal case) therefore got a silent `None` client here forever, with no error or warning, because a missing key and a present-but-unreachable key look identical to every caller (`FinnhubSentimentSource`, `llm/research.py`, `engine/agent_sentiment.py`) -- Finnhub contributed zero documents to every live cycle and to `scripts/backfill_sentiment_history.py`, indistinguishable in the logs from "Finnhub genuinely has no news this cycle." Confirmed live 2026-07-29: a real 6-month, 33-symbol backfill run against a real Finnhub key configured only in `.env` archived zero Finnhub documents; fixed to read `settings.FINNHUB_API_KEY`, re-verified live (248 real AMD headlines over 180 days). Existing tests masked this for years because they patch `os.environ` directly (`patch.dict(os.environ, {"FINNHUB_API_KEY": ...})`), which DOES set the real `os.environ` -- unlike a `.env` file -- so the tests never observed the discrepancy the fix corrects; updated to `patch("settings.settings.FINNHUB_API_KEY", ...)`, matching the Reddit/EDGAR test convention.

- **data/attention_sources.py** (Wikipedia-pageviews investor attention, 2026-07, follow-on to PR #416/#417) — Grounded in Da, Engelberg & Gao (2011), "In Search of Attention," *Journal of Finance* 66(5):1461-1499 (SVI spikes predict higher prices over the following ~2 weeks, with an eventual reversal). **Master switch: `settings.WIKIPEDIA_ATTENTION_ENABLED`, default `False`** — the sole call site, `pipeline/production_steps.py`'s `StrategyEvalStep`, is a complete no-op (zero network calls, `Attention_Score` stays `NaN`) until an operator sets this `True`, matching this codebase's other opt-in-networked-feature convention (`SENTIMENT_INGESTION_ENABLED`, `SECTOR_HEAT_ENABLED`). - **data/etf_holdings.py** (ETF constituent-holdings ingestion, 2026-07) — Grounded in Ben-David, Franzoni & Moussawi (2018), "Do ETFs Increase Volatility?", *Journal of Finance* 73(6):2471-2535 — ETF arbitrage propagates a shock in one constituent to its otherwise-healthy peers through the creation/redemption basket, so a heavily ETF-wrapped name carries extra non-diversifiable variance its own fundamentals do not explain; the paper's exposure measure is a QUARTERLY ownership share (ETF-held shares / shares outstanding), which is exactly the stock variable this module supplies. **Master switch: `settings.ETF_HOLDINGS_ENABLED`, default `False`** — `get_etf_holdings()` checks the gate FIRST, before any other work, and returns `{}` with ZERO network calls and ZERO DB reads, so a fresh clone / CI run never touches EDGAR (same opt-in-networked-feature convention as `SENTIMENT_INGESTION_ENABLED` / `SECTOR_HEAT_ENABLED` / `WIKIPEDIA_ATTENTION_ENABLED`). **NOT wired into scoring — nothing consumes it yet**: no `SignalModule`, no `settings.SIGNAL_WEIGHTS` entry, no `config.COLUMN_SCHEMA` column, no orchestrator call site; enabling it only populates the `etf_holdings` cache table and changes no score, weight, or order. **PRIMARY source is SEC N-PORT (NPORT-P) via EDGAR** — a fixed-schema, public-domain regulatory filing rather than a vendor convenience file — and every request goes through `data/edgar_fundamentals.py`'s EXISTING client (`_throttle`/`_http_get`/`get_cik`), which is mandatory, not stylistic: that module holds the process-wide lock that serializes request issuance inside SEC's ~10 req/s courtesy limit, so a second independently-throttled SEC client would blow the shared budget and throttle the platform's own fundamentals-backfill and 8-K paths too. **Honest freshness limitation, stated plainly:** N-PORT covers three month-ends and publishes ~60 days after quarter end, so served holdings run **1-5 months stale, always** — acceptable for the quarterly ownership-share stock variable the paper's measure is built from, and NOT acceptable as a real-time basket feed; any consumer needing today's composition must not use this module. **Network-call budget (only when enabled):** 1 process-lifetime fetch of `company_tickers_mf.json` (ticker → CIK + series id, double-checked-lock cached exactly like `edgar_fundamentals`'s CIK cache), plus per ETF per refresh 1 submissions-index fetch + at most `_MAX_FILINGS_PROBED` (4) primary-document fetches (a trust files one NPORT-P per series, so siblings may be probed before the requested `seriesId` is matched); a cache hit inside `ETF_HOLDINGS_REFRESH_DAYS` (default 7) makes ZERO requests. The loop is bounded by `settings.ETF_HOLDINGS_MAX_SECONDS_PER_CYCLE` (default 60 s — once elapsed, remaining ETFs are served from cache only) and `settings.ETF_HOLDINGS_CIRCUIT_BREAKER_THRESHOLD` (default 3 consecutive no-holdings outcomes), mirroring `ATTENTION_INGESTION_MAX_SECONDS_PER_CYCLE`/`ATTENTION_CIRCUIT_BREAKER_THRESHOLD`. **Causality / no-lookahead guarantee**, enforced in two independent places: (1) filing selection drops any filing whose report date is after `as_of` AND any filing whose **publication/filing date** is after `as_of` — the second check is the load-bearing one, since a filing covering 2024-03-31 that was not published until 2024-05-30 was unknowable on 2024-04-15; (2) `HistoricalStore.get_etf_holdings(..., as_of_date=X)` re-applies `as_of_date <= X` in SQL and returns the SINGLE most recent basket at or before the cutoff (never a union across quarters, which would sum weights past 1.0 and double-count names). `as_of=None` means "latest known" (live use). Dedicated tests: `tests/test_etf_holdings.py::TestAsOfCausality`. **NaN-never-fabricated contract (CONSTRAINT #4):** an unreported `weight` or `shares_held` is `NaN`, never `0.0` — N-PORT's `pctVal` is divided by 100 so the dataclass always carries a FRACTION of NAV, `shares_held` is populated only for share-denominated legs (`units == "NS"`; a bond's principal amount yields `NaN`, never a mis-scaled share count), a position with no `<ticker>` identifier is skipped rather than keyed by CUSIP, a document with no report date is dropped rather than stamped with today, and a symbol whose holdings could not be resolved is **absent** from the returned dict rather than present with an empty list ("unknown" and "holds nothing" are different claims). ### settings.LOCAL_DATA_ROOT

**Default:** `Path.home() / ".stockpy_local"` (e.g. `/Users/kevinlee/.stockpy_local`) — a machine-global root for every locally-generated model/data artifact, deliberately living OUTSIDE every git worktree/checkout. Auto-created (`mkdir(parents=True, exist_ok=True)`) the first time anything imports `settings`. Overridable via the ordinary `LOCAL_DATA_ROOT` env var / `.env` entry (e.g. to point at an external drive, NAS, or cloud-synced folder).

**Why:** this repo routinely runs many simultaneous git worktrees (the main checkout, per-agent worktrees, PR-review worktrees). Every one of the artifact paths below is untracked (`.gitignore`d by design), and git leaves untracked files worktree-local — so, before this, a model trained or a DB row written in one worktree was genuinely invisible from every other worktree's filesystem, even though nothing was deleted. Anchoring these paths to `settings.LOCAL_DATA_ROOT` instead of a repo-relative literal makes every worktree/checkout on the machine read/write the SAME physical files, with zero per-worktree `.env` setup, while git — structurally, not just via `.gitignore` pattern-matching — can no longer see any of it.

**Subfolder layout:**

| Path under `{LOCAL_DATA_ROOT}` | What lives there | Replaces (pre-2026-08) |
|---|---|---|
| `quant_platform.db` (+ `-wal` / `-shm`) | The SQLite trading DB (`db_config.resolve_database_url()`'s default), including the `forecast_errors` table written by `forecasting/forecast_tracker.py::ForecastTracker` (Tier 2.2 forecast-skill tracker) | `db_config.DEFAULT_DB_FILE` at the repo root |
| `output/` | `state_snapshot.json`, `history/`, `daemon.json`, `decision_log.jsonl`, `runtime_flags.json`, `prompt_cache/`, `rag_index/index.faiss`, `sector_embedding_cache.json`, … (unchanged internal structure) | `settings.OUTPUT_DIR`'s old repo-root `output/` |
| `logs/` | `investyo.log` (rotating handler) and other platform logs | `alerting._LOGS_DIR` at the repo root |
| `ml_models/` (+ `ml_models/forecast_cache/`) | Trained `.pkl`/`.keras` model artifacts and the CNN-LSTM per-ticker forecast cache — see `docs/architecture/ml-and-reports.md` | `ml/lgbm_ranker._MODELS_DIR`, `ml/meta_labeling._MODELS_DIR`, `ml/forecast_backfill._MODELS_DIR`, `forecasting/model_persistence.MODELS_DIR` |
| `ml_feature_cache/` | The PIT feature-engineering cache | `ml/data/store._CACHE_DIR` |
| `universe_cache.parquet` | S&P 500 constituent cache | `universe_engine.CACHE_PATH` |
| `api_cache/cache.db` | The general slow-changing-data SQLite cache (`cache/cache_store.py`) | `cache/cache_store._DEFAULT_DB_PATH` |
| `robinhood_cache/` (`account_snapshot.json`, `robinhood_orders.json`, `sync_report.json`) | Daily Robinhood account/orders/sync-report JSON caches | 3 modules' own `_CACHE_PATH` under the repo-root `cache/` dir |

`ml/registry.yaml` is NOT relocated — it stays tracked in-repo, pointing at the artifacts above by filename convention only (see `docs/architecture/ml-and-reports.md`). Migrating the ~1.7GB of pre-existing artifacts already sitting at their old repo-relative paths is an explicit, opt-in, re-runnable step — `scripts/migrate_to_local_data_root.py` (`--dry-run` default, `--apply` to actually move, `--verify` for a post-migration sanity report) — never automatic on process start.

**Incident note (2026-08, fixed in PR #720):** `forecasting/forecast_tracker.py`'s `ForecastTracker.__init__` was missed by the original migration inventory and kept a hardcoded, CWD-relative `db_path="quant_platform.db"` default that bypassed `db_config.resolve_database_url()` entirely, so its `forecast_errors` table kept writing to the old repo-relative location for hours after the live daemon restarted onto the merged migration. It now resolves its default the same way every sibling store does. See `docs/known_issues/forecast_tracker_local_data_root_split.md` for the full write-up.
