# Architecture: ML Pipeline, Report Templates & AI Auditor

> Part of the split-out `CLAUDE.md` System Architecture reference. See [../../CLAUDE.md](../../CLAUDE.md) for the index.

- **ml/** — Machine learning pipeline in a three-tier qlib-style architecture (no qlib dependency). Three sub-packages:
  - **ml/data/** — Point-in-time feature store and label construction. `PITFeatureStore` caches daily cross-sectional snapshots as Parquet files under `{settings.LOCAL_DATA_ROOT}/ml_feature_cache/` (2026-08 — was `ml/data/cache/`; see `docs/architecture/data-layer.md`'s `settings.LOCAL_DATA_ROOT` subsection). `build_meta_features(base_df, primary_score)` extends the base PIT feature matrix with the primary signal's own score for MetaLabeler training.
  - **ml/models/** — Model ABC (`ml/models/base.py`) with abstract `fit(X, y, t1)/predict(X)/save/load` interface. Both `LGBMCrossSectionalRanker` and `MetaLabeler` implement this ABC so the strategy layer can consume them uniformly. The `.py` model-class modules themselves stay tracked in-repo under `ml/models/`; the binary `.pkl`/`.keras` artifacts those classes `save()`/`load_latest()` now live under `{settings.LOCAL_DATA_ROOT}/ml_models/` (2026-08), not alongside the `.py` files.
  - **ml/strategies/** — `StrategySpec` data container linking a Model to a `signal_id` and flagging whether it is a meta-labeler.
  - **ml/registry.yaml** — Production model registry: model role, path, `trained_date`, `cpcv_dsr`, `pbo`, `deployable` flag. Updated by retraining jobs. Stays tracked in-repo for version control, while `settings.LOCAL_DATA_ROOT / "ml_models" / "registry.yaml"` provides the single machine-global runtime source of truth across git worktrees (dual-persisted by `ml/registry_io.py`). Every reader in the codebase (`pilots/models.py`, `ml/meta_bootstrap.py`, `gui/panels/analytics_signals.py`, `gui/panels/analytics.py`, `investyo_mcp_server.py::get_model_registry_status`, `Gravity AI Review Suite.py`'s qlib-arch registry audit) resolves via the single shared `ml.registry_io.resolve_registry_path()`/`load_registry()` so none of them can disagree with each other after a git operation reverts the repo-tracked copy; `pilots/models.py` additionally performs self-healing discovery against newer dated `.pkl` binaries on disk, nulling out `cpcv_dsr`/`pbo`/`deployable` (rather than pairing them with the newer date) when the on-disk artifact doesn't match the registry's own validated `artifact_file`. Points at the real `.pkl` files by **filename convention only**: `artifact_file` (e.g. `lgbm_20260814.pkl`) is a bare filename, resolved against `{settings.LOCAL_DATA_ROOT}/ml_models/` at load time — never a path. The registry's `path:` field (e.g. `ml/models/lgbm_latest.pkl`) is a separate, older, purely informational/provenance field the runtime loader never reads (`<Class>.load_latest()` glob-sorts dated files in `{settings.LOCAL_DATA_ROOT}/ml_models/` directly).
  - **`scripts/train_lgbm.py::run_training`'s `confirm_shared_write` guard (2026-08-22)** — a real incident (not theoretical): an ad hoc `run_training()` call with no `save_path`/`registry_path` override silently wrote synthetic-run metrics into the MACHINE-GLOBAL `ml/registry.yaml` (`update_model_metrics(path=None)`'s dual-persistence writes to BOTH `settings.LOCAL_DATA_ROOT/ml_models/registry.yaml` AND, via the hardcoded `_DEFAULT_REGISTRY_PATH` constant in `ml/registry_io.py`, the repo-tracked `ml/registry.yaml` — the LATTER is unconditional and settings-independent, so even redirecting `settings.LOCAL_DATA_ROOT` alone does not fully isolate a call) and left a bogus model pickle in the shared `ml_models/` directory that `LGBMCrossSectionalRanker.load_latest()` (a plain glob-sort of dated filenames) would have picked up over the real production model — caught and reverted by hand (see `docs/VALIDATION_STRATEGY_FIX_LOG.md`'s 2026-08-22 `lgbm_ranker` entry). Fixed by requiring an explicit `confirm_shared_write: bool = False` keyword whenever `save_path` and/or `registry_path` are left `None` — `run_training()` now raises `ValueError` immediately (before any network/training work starts) rather than silently proceeding. The two genuine, deliberate production callers — `scripts/train_lgbm.py`'s own CLI `main()` and `scripts/retrain_models.py`'s scheduled retraining job — pass `confirm_shared_write=True` explicitly; every test in the suite already passes explicit, isolated `save_path`/`registry_path` and is unaffected. See `tests/test_train_lgbm.py::TestSharedStateGuard` for the regression coverage (including a test proving the escape hatch itself works — via fully mocking the save/registry calls rather than trying to redirect every internal path-resolution branch, after an earlier draft of that same test tried the redirect approach and itself leaked a write into the real machine-global registry).
  - **ml/triple_barrier.py** — Lopez de Prado (AFML Ch. 3) triple-barrier labeling. Three functions:
    - `get_volatility(close, span=100) -> pd.Series` — Daily EWMA vol from log-returns (strictly PIT: `adjust=False`, causal).
    - `cusum_filter(close, threshold) -> pd.DatetimeIndex` — Sequential CUSUM event sampler (inherently sequential; scalar loop is correct here). Returns timestamps where cumulative log-return drift first crosses ±threshold. Raises `ValueError` for empty series or threshold ≤ 0.
    - `apply_triple_barrier(events, close, pt_sl_multiples=(2.0,1.0), vertical_barrier_days=5) -> pd.DataFrame` — For each event at t₀: sigma is computed from `get_volatility(close[:t₀])` (PIT), upper/lower barriers are price-based (`entry * (1 ± mult * sigma)`), vertical = t₀ + N business days. Label: +1 (upper), -1 (lower), 0 (vertical). Returns DataFrame indexed by t₀ with columns `[t1, barrier_hit, label, entry, upper_level, lower_level]`. Perturbing `close[t₀+1:]` never changes barriers for event at t₀.
  - **ml/meta_labeling.py** — `MetaLabeler(signal_id, lgbm_params)` binary LightGBM classifier predicting P(primary_signal_correct). Implements Model ABC. Key methods: `fit_from_primary(X, y_primary, y_barrier)` builds meta-label target (1 = direction correct, 0 = wrong/vertical), filters neutral-signal events, trains. `predict_proba_scalar(X_today) -> float` returns the mean P(correct). Returns 1.0 (neutral/no-op) before training. Monthly retraining: `needs_retrain(retrain_freq_days=30) -> bool`. Saved as `{settings.LOCAL_DATA_ROOT}/ml_models/meta_<signal_id>_<YYYYMMDD>.pkl` (2026-08 — was `ml/models/meta_<signal_id>_<YYYYMMDD>.pkl`). `MetaLabelerRegistry` (global singleton `global_meta_registry`) maps `signal_id -> MetaLabeler`; imported by `signals/aggregator.py`.
  - **ml/options_meta_labeler.py** — `OptionsMetaLabeler`: Stage 4 ML meta-labeler for quantitative multi-leg options strategies. Conditions on entry volatility surface (IVR, VRP, VIX), target DTE, credit-to-width ratio, and short-leg delta to predict calibrated win probability P(Win). Predicts dynamic sizing multipliers $\in [0.30, 1.50]$ (or $0.0$ to hard-reject low-confidence trades) for `execution/options_paper_executor.py` when `settings.OPTIONS_META_LABELER_ENABLED=True`. **Serving-time gate-safety fixes (2026-08-22)**: `execution/options_paper_executor.py::get_actionable_directives` previously omitted 4 of the model's inputs (`vrp`/`vix`/`short_delta`/`credit_to_width_ratio`) entirely, silently triggering hardcoded-constant defaults on every live prediction regardless of actual market conditions — all four now resolve from the real `vrp`/`macro_dto` params and the directive's own `Short_Strike`/`Long_Strike`/`Short_Delta`/`Net_Premium` fields, `None` (never fabricated) when unresolvable. `predict_probability` now gates on feature finiteness (`np.isfinite`) BEFORE ever calling the model — a required feature that is present-but-`NaN`/`None` (not merely absent) previously sailed through as a normal value and produced an overconfident, possibly INCREASED prediction; it now declines to score and returns the neutral 0.65/1.0x fallback, surfaced via `score_option_directive`'s new `features_resolved` key. The degenerate (single-outcome) training path's `predict_probability` branch is now clipped to `[0.05, 0.95]` like the other two model branches, instead of returning an unclipped, absolute 0.0/1.0 forever. `trend_bias` was DROPPED from the model's feature vector entirely (not fixed to match) — it meant a different thing at train time (a pure function of strategy name, collinear with the one-hot strategy columns) than at serve time (a real Aroon/Coppock technical signal); the field remains on `OptionsTradeFeatureRow` for backward-compat construction but is unused. `execute_strategy_directives`'s ML-gating exception handler now fails CLOSED (skips the trade, logs at WARNING) instead of silently falling through to full un-derated size on any scoring exception. `train()`'s returned metrics (and the two `api/pilots_api.py` meta-model endpoints) now carry `metrics_are_in_sample: True` — no purged/held-out CPCV evaluation exists for this model, so these are optimistic, in-sample-only numbers, not a validated metric (full CPCV integration is a disclosed, separate follow-up). See `docs/known_issues/options_meta_labeler_serving_time_gaps.md` for the full incident write-up.
  - **`SignalAggregator` Stage 4 wiring (signals/aggregator.py)**: For each active signal module, the aggregator now checks `global_meta_registry.has(name)`. If a MetaLabeler is registered, it calls `get_proba(name, feature_row)` where `feature_row` is the current `row` Series as a DataFrame plus `primary_score = output.score`. If `proba < settings.META_LABEL_MIN_CONFIDENCE` (default 0.4), a `meta_hard_gate` flag is set and `meta_label_composite` is forced to exactly `0.0` (which zeroes the Kelly Target for this cycle). When no MetaLabelers are registered (the default), behavior is identical to pre-Stage-4 (all `meta_label_proba = 1.0`, composite = 1.0).

  - **`settings.META_LABEL_MIN_CONFIDENCE`** — New setting (default 0.4). The P(correct) threshold below which the meta hard gate fires. Controlled via `.env`.
  - **`ml/training_data.py::build_training_panel`** — the point-in-time training-panel builder; among its features is `paper_size_vs_kelly_ratio_30d` (`total_qty / target_qty`, sourced from paper-broker order history). **Known limitation**: this feature currently reads as a constant `1.0` for all real production data — `target_qty` and `qty` are populated from the same already-fully-sized/post-portfolio-cap value at the only production order-submission call sites (`main_orchestrator.py`'s BUY/SELL `OrderIntent` construction), so there is no distinct pre-cap target for the ratio to compare against. Making this genuinely informative would require threading a separate pre-portfolio-cap target quantity through to order submission.
  - **Phase 5 model build-outs (2026-08)**: of the four `ml/models/{sf_garch_lstm,bond_bert,garch_midas,emoji_sentiment}.py` stand-ins flagged by their own "HONEST STATUS" docstrings (all four were closed-form ridge regression despite their names, per PR #538/#539's honesty audit), two are now genuinely real, and two remain honestly out of scope. **`SFGarchLSTMModel`**: a real GJR-GARCH(1,1) (fit via `arch`, causal one-step-ahead recursive conditional-variance feature — see `_gjr_garch_conditional_vol`'s own perturbation-tested causality) + an optional sentiment-factor channel (when the caller supplies a pre-computed `sentiment_score` column, e.g. from `signals/news_catalyst.py`'s real FinBERT scores) + a genuine single-layer LSTM sequence regressor, run through `cnn_lstm_worker.py`'s existing TF-subprocess-isolation pool (a NEW `fit_predict_or_infer_lstm` function there, reusing the same import-order-deadlock fix rather than adding a second TF entry point — required, not optional, here, since this model is routinely imported into a process that already imported pandas, which provably defeats the "import tensorflow first" guard `forecasting_engine.py` uses). Degrades to the original ridge-regression baseline (now an honestly-documented fallback tier) when TensorFlow is unavailable, the subprocess call fails, or there's too little history for a meaningful train/val split — never fabricates, never crashes. **`EmojiSentimentModel`**: real emoji-lexicon parsing (`data/emoji_lexicon.py`, a hand-curated ~100-emoji polarity table — explicitly NOT a verbatim third-party dataset import, mirroring `signals/news_catalyst.py`'s own hand-built keyword-lexicon convention) plus a real social-volume channel, both folded into an actual ridge regression against `y` (the original version ignored `y` entirely). Falls back to fitting ridge on whatever numeric columns are present when the caller supplies no `social_text`/`social_volume` columns. **`BondBertModel`/`GarchMidasModel` remain ridge-regression stand-ins** — a real BondBERT needs fine-tuning a transformer on bond-specific text (no pretrained model exists to reuse, and curating labeled training data is its own project); a real GARCH-MIDAS needs a genuine MIDAS Beta-weighted lag-polynomial implementation over macro series. Neither has been registered in `ml/registry.yaml` or wired into a production caller — this repo's sandboxed dev/CI environment has no live-market network access to run a real `validation/harness.py` PBO/DSR/Sharpe pass, so no registry entry would be honest. Tests: `tests/test_sf_garch_lstm.py`, `tests/test_emoji_lexicon.py`, `tests/test_emoji_sentiment_model.py`, `tests/test_cnn_lstm_worker.py::TestFitPredictOrInferLstm`.
- **reports/cpcv_report.html.j2** — Plotly/Jinja template for the dedicated per-path CPCV Sharpe table and OOS Sharpe-distribution histogram. Previously dead code (nothing rendered it, despite `validation/harness.py` already computing and threading `paths`/`distribution`/`n_trials` into a different template's render context). Rendered by `StrategyValidationHarness._render_cpcv_report()`, called from `run()` right after `_render_html_report()`, to `<reports_dir>/cpcv_<strategy>_<timestamp>.html`. `ValidationReport.mean_oos_sharpe` (CPCV mean OOS Sharpe across all combinatorial paths — distinct from `.sharpe`, the full-sample net-of-cost Sharpe used by the deployable gate) exists solely to feed this template.
- **reports/validation_report_template.html.j2** — Jinja2 template for rendering validation reports. Rendered by `_render_html_report()`; still receives `paths`/`distribution`/`n_trials` in its render context but does not display them itself — that's `cpcv_report.html.j2`'s job.
- **llm/research_copilot.py** — `ResearchCopilot`: Quantitative AI research synthesis engine. Ingests natural language hypotheses, formulas, or papers and synthesizes AST-safe vectorized `SignalModule` code with strict AST validation (`validate_ast_safety`) and metadata extraction (`extract_strategy_metadata`).
- **validation/autonomous_backtest_runner.py** — `AutonomousBacktestRunner`: Autonomous CPCV backtest execution engine. Runs combinatorial purged cross-validation over historical OHLCV data, computes PBO, DSR, and Sortino, and evaluates strategies against single-source-of-truth deployability gates. **CONSTRAINT #4 NaN-honesty fix (2026-08):** `run_cpcv()` previously injected a fabricated `-999.0` sentinel for a degenerate/NaN Sharpe on BOTH the in-sample and out-of-sample legs of `is_sharpe_matrix`/`oos_sharpe_matrix`, and `mean_is_sharpes` further substituted a fabricated `0.0` for the sentineled entries before computing `sr_var` (the DSR variance input). Both legs now preserve the genuine `NaN`, mirroring `validation/metrics.py::run_cpcv_evaluation`'s own `_nanmean_or`/`finite_mean_is_sharpes`-style NaN-filtered aggregation (no per-path best-trial `argmax` selection exists in this file's `run_cpcv` — the candidate strategy is always trial index 0 — so no `_rank_key`-equivalent guard was needed here). This also newly exercises `probability_of_backtest_overfitting()`'s own NaN-comparison guard (see `validation/metrics.py` below) for this call site, since a real NaN can now reach it instead of a sentineled placeholder.
- **ml/drl_market_maker.py** — Phase 22 of `.claude/giant_master_plan.md`. The genuine, well-tested part is a real Avellaneda-Stoikov (2008) closed-form quoting engine — reservation price `R(s,q,t)=s-qγσ²(T-t)`, optimal spread, Poisson fill intensities, inventory-penalized reward `ΔPnL − λ_inv·q²·dt` — all matching the spec exactly and reachable live via `simulate_market_maker_session` (`api/pilots_api.py`, `MarketMakerAgentView.tsx`). **The plan's "Deep RL / PPO" claim does not hold, per the 2026-08-17 audit (`.claude/giant_master_plan_audit.md`): `train_market_maker_policy`'s own docstring calls it a "lightweight heuristic and policy optimizer"; the body is a 2-parameter (γ, κ) stochastic hill-climb, not a neural network or policy-gradient method.** As of PR #788, `POST /pilots/options/market-maker/train` (`api/pilots_api.py`) now calls it -- closing the "never imported by `api/pilots_api.py`" half of the 2026-08-17 finding -- but it remains backend-only: no webapp component calls this endpoint and it has no dedicated test coverage. The only live-reachable, UI-wired path is still the deterministic quoter (`simulate_market_maker_session`), not a trained/optimized policy. Not in `STRATEGY_REGISTRY`; no documented reasoning exists anywhere for why the standard PBO/DSR gate doesn't apply to an RL-shaped policy — a real, legitimate question with no written answer yet.
- **ml/drl_market_maker_ppo.py** (2026-08-19) — closes the "Deep RL (PPO)" audit finding against the module above: a genuine actor-critic PPO agent (Schulman et al.) learning a state-dependent `[delta_bid, delta_ask]` quoting policy via GAE and a clipped surrogate objective, implemented in pure NumPy with hand-derived backprop verified against finite-difference gradients (`torch` is listed in `requirements-optional.txt` but is not actually installed in this environment). First-training-run comparison against the closed-form Avellaneda-Stoikov quoter found higher PnL/Sharpe but also higher inventory risk — a real reference point, not a validated win (full numbers in `docs/VALIDATION_STRATEGY_FIX_LOG.md`'s 2026-08-19 entry). Not wired to any API endpoint, webapp screen, or `STRATEGY_REGISTRY` entry as of this writing — a separate follow-up. Tests: `tests/test_drl_market_maker_ppo.py` (12 tests, incl. the gradient-correctness check).
- **ml/transformer_vol_forecaster.py** — Multi-Quantile Temporal Fusion Transformer (TFT) Volatility Forecaster (Phase 33). From-scratch multi-head attention + Gated Linear Units (GLU) with Pinball Loss optimization ($\mathcal{L}_\alpha(y, \hat{y}_\alpha) = \max(\alpha(y - \hat{y}_\alpha), (\alpha - 1)(y - \hat{y}_\alpha))$) for multi-quantile ($q_{10}, q_{50}, q_{90}$) volatility surface projection. Features strictly causal FRED macro indicator conditioning (`VIXCLS`, `T10Y2Y`, `BAMLC0A0CM`, `FEDFUNDS`) with lookahead-free alignment and monotonic quantile rearrangement. Verified with 13 unit and causal perturbation tests in `tests/test_transformer_vol_forecaster.py` (this closes the 2026-08-17 audit's lookahead-coverage gap, also independently fixed by PR #771 F3). The live `GET /pilots/options/ai/transformer-forecast` endpoint fits on REAL historical bars for the requested symbol (PR #771 F7's fix, carried forward here) rather than a dummy tensor, degrading to an honest HTTP 422 on insufficient history. Rendered in `TransformerVolForecastView.tsx`.
- **validation/synthetic_diffusion_engine.py** — Macro-Regime Guided Generative Diffusion Stress Engine (Phase 34). Continuous-time score-based diffusion model trained with Classifier-Free Guidance (CFG, $p_{\text{uncond}} = 0.15$) to generate conditioned tail-crisis paths across 5 macro regimes (`unconditional`, `vol_shock`, `credit_freeze`, `stagflation`, `liquidity_squeeze`). Solves reverse-time Ornstein-Uhlenbeck SDE via Euler-Maruyama integration: $\mathrm{d}X_t = \left[-X_t - 2 \tilde{s}_\theta(X_t, \tau, c)\right] \mathrm{d}\tau + \sqrt{2} \mathrm{d}W_\tau$ with guided score $\tilde{s}_\theta = (1 + w) s_\theta(x, \tau, c) - w s_\theta(x, \tau, 0)$. Computes multi-quantile tail risk ($\text{VaR}_{95}, \text{CVaR}_{95}, \text{VaR}_{99}, \text{CVaR}_{99}$). Surfaced via `POST /pilots/options/ai/diffusion-stress-test` and rendered in `GenerativeDiffusionStressView.tsx`.
- **ai_verification_prompts.py** ("Gravity AI Auditor") — 6-step static-analysis + simulation sandbox (via OpenAI/Anthropic) that strategies must pass before deployment.
