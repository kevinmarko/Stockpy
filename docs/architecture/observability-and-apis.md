# Architecture: Observability & Read-Only APIs

> Part of the split-out `CLAUDE.md` System Architecture reference. See [../../CLAUDE.md](../../CLAUDE.md) for the index.

- **observability/__init__.py** — Empty package marker.
- **observability/alerts.py** — `send_alert(level, message, channels=None, extra=None) -> None` dispatches to zero or more output channels: `console` (always active via Python logging), `file` (JSONL at `settings.ALERT_FILE_PATH`), `discord` (`settings.DISCORD_WEBHOOK_URL`), `slack` (`settings.SLACK_WEBHOOK_URL`), `email` (SMTP via `settings.ALERT_SMTP_*`). `_active_channels()` auto-detects configured channels. Discord payload: `{"content": "🚨/⚠️/ℹ️ **[LEVEL]** \`timestamp\`\nmessage"}`. Slack payload: `{"text": "..."}`. Email: MIMEText via `smtplib.SMTP` STARTTLS. All channel failures are caught and logged — a broken webhook must never crash the pipeline. Alert rules: CRITICAL for kill switch, reconciliation drift, broker lost, missing validation report; WARNING for heat >5%, correlation concentration, large slippage; INFO for fills, rebalance. `send_daily_summary(pnl_summary, warnings)` composes a multi-line INFO alert with P&L and warnings. **Pipeline-stall watchdog consumer (2026-08 fix)**: `desktop/daemon_runtime.py::OrchestratorDaemon.maybe_alert_on_pipeline_stall()` (gated on `settings.PIPELINE_STALL_ALERT_ENABLED`, default `True` — a deliberate exception to this repo's usual "new instrumentation defaults off" convention, since this is pure read-only alerting with zero external blast radius when no webhook/email channel is configured) reads `reporting.progress.read_progress()` and fires a `WARNING` with `dedup_key="pipeline_stall"` whenever a cycle's `state == "running"` with no progress update for longer than `settings.PIPELINE_STALL_ALERT_SECONDS` (default 1800s) — added after a real incident where a wedged cycle went unnoticed for 2.5 days because the daemon's own APIs stayed responsive throughout (see `docs/known_issues/data_pipeline_fred_unbounded_timeout_stall.md`). The existing `dedup_key`/`settings.ALERT_DEDUP_WINDOW_SECONDS` mechanism means a persisting stall re-fires as a periodic reminder rather than going silent after the first alert. Called from both of `_timer_loop`'s per-wake spots and from `trigger_run()` directly (covers `settings.ORCHESTRATOR_INTERVAL_SECONDS <= 0`, its actual default, where `_timer_loop` parks on an untimed wait and would otherwise never get a periodic chance to check). Deliberately alert-only — never cancels the wedged cycle or restarts the daemon process, since this same process also hosts the Control/Pilots APIs the webapp depends on.
- **observability/dashboard.py** — **Retired.** The standalone Streamlit paper-trading observability dashboard has been removed; its panels are folded into the Command Center's Observability tab (`gui/panels/observability.py`) so there is a single always-on surface instead of two separately-launched Streamlit apps.
- **api/state_api.py** — **Standalone, read-only FastAPI service** over the file-backed state the engine and UI already communicate through — a foundation for a future web/mobile frontend, **deliberately NOT wired into any orchestrator, the desktop shell, or the GUI**. Endpoints: `GET /health` (liveness of the API process, ALWAYS open — no auth — so a load balancer/watchdog can probe without a token), `GET /state` (full parsed `output/state_snapshot.json`, 404 if absent), `GET /signals` (just the `signals` list from that snapshot), `GET /trades` (closed trades via `transactions_store.TransactionsStore`, `[]` when none). **AST-guard invariant:** it only reads already-persisted state and NEVER imports engine/calculation modules (`processing_engine`, `strategy_engine`, `forecasting_engine`, `macro_engine`, …) or broker/execution modules (`execution/*`). **CORS** via `CORSMiddleware` restricts browser origins to `settings.CORS_ALLOWED_ORIGINS` (GET-only, `allow_credentials=False`). **Bearer-token auth** (`require_token` via built-in `HTTPBearer`): when `settings.STATE_API_TOKEN` is set, `/state`/`/signals`/`/trades` require `Authorization: Bearer <token>` (constant-time compare via `hmac.compare_digest`, 401 on mismatch/missing); `/health` is always open. **FAIL-OPEN** when `STATE_API_TOKEN` is unset/empty (the three data endpoints are unauthenticated for zero-config local use, with a startup WARNING logged). The token is NEVER logged (CONSTRAINT #3). Dead-letter resilient (CONSTRAINT #6): a missing/unreadable/invalid snapshot degrades to `None`→404 and a DB read failure degrades to `[]` — it never fabricates a placeholder/synthetic snapshot (CONSTRAINT #4). Launch standalone: `uvicorn api.state_api:app --port 8600` (no new dependencies — fastapi/uvicorn already in requirements.txt, `HTTPBearer` is built into fastapi). **New env vars:** `STATE_API_TOKEN` (secret bearer token; when set, `/state` `/signals` `/trades` require `Authorization: Bearer <token>`, 401 otherwise; unset = fail-open for local use), `CORS_ALLOWED_ORIGINS` (JSON list of allowed browser origins, default `["http://localhost:3000"]`).
- **api/control_api.py** — **Separate FastAPI app from `api/state_api.py`** (deliberately — `state_api.py`'s read-only purity is AST-guard-enforced to never import engine/execution modules; this module's whole purpose is to reach the daemon and the kill switch, so it needs its own file and its own auth posture). Hosted INSIDE the orchestrator daemon process by `desktop/orchestrator_daemon.py` (not standalone-launchable the way `state_api.py` is). `set_daemon(daemon)`/`get_daemon()` module-level registry, wired by the daemon entrypoint after `daemon.start()`. Endpoints: `GET /health` (always open — `{"status": "ok", "daemon_alive": bool}`); `GET /status` (fail-open read token, mirrors `state_api.py`'s `STATE_API_TOKEN` posture — daemon status, `last_run`, kill-switch state, `advisory_only`, `dry_run`); `POST /run` (**FAIL-CLOSED** command token via `settings.ORCHESTRATOR_DAEMON_TOKEN` — unlike `STATE_API_TOKEN`, unset means the endpoint is DISABLED entirely (403), not open, since triggering a real pipeline run is a materially different risk than reading persisted state; checks auth first, then `execution.kill_switch.GlobalKillSwitch` — 423 if active — then `daemon.trigger_run(reason="manual")` — 202 + run_id on success, 409 + the existing run_id if one is already in flight); `GET /run/{run_id}/status` (200 with `state: "running"` for an in-flight run — NOT a 404 — or 404 for a truly unknown id); `GET /run/latest` (404 only when nothing has ever been triggered); **`PUT /interval`** (2026-07, live interval setter — command-token guarded ALONE, same posture as `POST /run`, since a live setter has no persistence to protect unlike `.env`; pydantic body validated via the shared `settings.validate_interval_seconds`; calls `daemon.set_interval(body.interval_seconds)` and echoes `{"interval_seconds": ...}` — see `desktop/daemon_runtime.py` above); **`POST /daemon/restart`** (command-token guarded, same fail-closed posture as `POST /run`; **409** while `daemon.is_running` — that is a **`@property`** on `OrchestratorDaemon`, read WITHOUT parens: `daemon.is_running()` raised `TypeError: 'bool' object is not callable` and shipped as a 500 on every daemon-attached request until fixed 2026-07-31 — see `tests/test_control_api.py`'s `_FakeDaemon` and its `test_daemon_properties_are_never_called_as_methods` AST guard, which derives the property set from the real class and would independently catch a regression; on success arms `threading.Timer(0.5, os._exit, (0,))` — `os._exit`, *not* `sys.exit()`, because uvicorn is hosted on a background thread inside `desktop/orchestrator_daemon.py` and `SystemExit` would only kill that thread — and returns `{"restarting": true, "message": ...}`. Honest by construction: promises a clean exit, never a respawn — `deploy/investyo-daemon.service` (`Restart=always`) and `scripts/com.investyo.stack.plist` (`KeepAlive`) do respawn; the plain `app_shell.py` → `gui.orchestrator_runner.launch_daemon_engine` `Popen` path does not, and this endpoint has no way to tell which it is in. Deliberately does **NOT** 503 when no daemon is attached, unlike every other endpoint here — this API lives *inside* the daemon process, so "no daemon attached" still means this process can be exited. Surfaced in the PWA by `webapp/src/screens/Settings.tsx`'s `RestartDaemonControl` behind a typed-"RESTART" confirm, routed to port 8601 by `client.ts`'s `baseFor` `/daemon/` prefix); **`GET /runs/history`** (2026-07, new — durable run history, read-token guarded like `GET /status`; reads `desktop/run_history_store.py`'s `pipeline_runs` DB table via `RunHistoryStore(readonly=True).get_recent(limit)`, `limit` query param clamped to `[1, 200]` (default 50), degrades to `[]` on a DB read failure rather than a 500; deliberately has NO daemon-not-attached branch — unlike every other endpoint here, the whole point is to keep serving history across a daemon restart, exactly when `GET /status`'s in-memory `run_history` ring is empty). CORS mirrors `state_api.py` but adds `POST`/`PUT` to `allow_methods`. Both bearer-token guards use `hmac.compare_digest`; tokens NEVER logged (CONSTRAINT #3).
- **pilots/ (Autopilot-style Pilots layer)** — packages Stockpy's OWN strategies as copyable "Pilots" for the consumer-style PWA, read entirely from already-persisted state (no heavy-engine imports on the read path). **`pilots/catalog.py`** — frozen `Pilot` dataclass (`id`, `name`, `category`, `description`, `weights` — a subset of `settings.SIGNAL_WEIGHTS` keys, `long_only`, `validation_strategy_id` — the explicit join to `scripts.refresh_validations.STRATEGY_REGISTRY`) + the static `PILOTS` catalog (9 pilots: single-signal `trend-following`/`dip-buyer`/`macd-trend`/`multifactor`/`cross-sectional-momentum`/`dividend-income`/`deep-value` plus curated blends `value-quality`/`balanced-blend`) + `list_pilots()`/`get_pilot(id)`. **The three namespaces genuinely differ** (signal `name`==SIGNAL_WEIGHTS key ≠ STRATEGY_REGISTRY key: e.g. the MACD pilot blends `macd_momentum`+`aroon_trend` signals but joins the `macd_trend` backtest; `multifactor`→`multifactor_lowvol_size`); pilots with no honest backtest carry `validation_strategy_id=None` rather than borrowing another strategy's Sharpe (CONSTRAINT #4). **`pilots/scoring.py`** — pure snapshot math: backs out each module's raw score via `raw = score_components[m] / SIGNAL_WEIGHTS[m]` (guards the weight-0 `regime_multiplier` divide-by-zero; a module missing from a symbol contributes 0, never fabricated), re-blends under `pilot.weights`, keeps positives, normalizes top-N (sort→truncate→normalize so weights sum to 1.0 over exactly the shown holdings) via `pilot_holdings`; `sector_allocation` group-by; `pilot_trades` diffs consecutive `output/history/` snapshots (reusing `scripts.snapshot_diff` conventions) into ENTER/EXIT/REWEIGHT events. Dead-letter safe (missing/malformed → `[]`/`None`). **`pilots/performance.py`** — reads `reports/<validation_strategy_id>_validation_summary.json` (schema = `validation/harness.py::ValidationReport.to_summary_dict()`); `pilot_headline`/`pilot_performance` return metrics plus the REAL downsampled base-100 OOS equity `curve` the harness now persists as `equity_curve` (built from the same net-of-cost return series that feeds Sharpe/MaxDD — `validation/harness.py::_build_equity_curve`, ≤`MAX_EQUITY_CURVE_POINTS`=120 points), tail-sliced to the requested `range` (`_slice_curve_by_range`, an honest zoom — never a re-simulation). `curve=None` + honest `reason` only when the Pilot has no `validation_strategy_id`, the summary is missing, or it predates the `equity_curve` field / had no meaningful returns — NEVER synthesized (CONSTRAINT #4). `benchmark` is the REAL persisted base-100 buy-&-hold-of-the-underlying curve the harness now persists as `benchmark_curve` (the harness's `y` return series aligned to the same OOS index as `equity_curve`), tail-sliced to the same `range`; falls back to `macro_benchmark_curve` (SPY) if the strategy's specific benchmark is missing, or `None` if neither is available. **`pilots/follows_store.py`** — `FollowsStore` atomic write-then-rename JSON at `output/follows.json` (`{version, follows:[{pilot_id, amount, created_at, updated_at, status}]}`); `upsert` (amount 0 = cancel), `remove`, and the marketplace `aum_proxy`/`followers_proxy` (real local sums, not fake). Each follow row additionally carries an ADDITIVE, backward-compatible per-follow **`mirrored`** set — the last-mirrored holding set (`[{symbol, weight, target_notional}]`) + a `mirrored_updated_at` timestamp — written by `set_mirrored(pilot_id, mirrored)` (updates the row in place, or creates a minimal `pilot_id`+`mirrored` row with NO fabricated `amount`/`status` so the AUM/followers proxies are unaffected) and read by `get_mirrored(pilot_id)` (returns `[]` — the honest "no attribution" signal — when the row is missing, the field is absent on a legacy row, or it's malformed). This is the per-follow position attribution that powers `pilots/mirror.py`'s force-exit of dropped names; legacy rows written before the field existed load fine. **`pilots/mirror.py`** — the gated auto-mirror. **`build_follow_targets(pilot, amount, snapshot, top_n=None)`** (renamed from the private `_current_target_holdings`, 2026-07 composer refactor) is PURE target-notional math — for each holding `target_i = amount * weight_i` (clamped by `settings.ROBINHOOD_MAX_NOTIONAL_PER_ORDER`), NO account snapshot, NO current-holdings netting, NO BUY/SELL decision — the shared primitive `execution/compose.py`'s multi-source netting is built on (see that module's CLAUDE.md entry for WHY netting must happen exactly once, centrally, never per-Pilot). **`build_follow_intents(pilot, amount, account_snapshot, ...)`** is now a thin single-source wrapper: it builds this Pilot's `build_follow_targets(...)` + a `dropped` list (any `prior_mirrored` row whose symbol fell out of the fresh targets) into an `execution.compose.FollowSourceClaims`, and delegates the actual rebalance-to-target math (net off the follower's CURRENT market value, **BUY** when underweight / **SELL partial trim** when overweight, no-trade band, force-exit of dropped-but-still-held names capped by attribution) to `execution.compose.compose_targets` — verified byte-identical against all 41 pre-existing tests in `tests/test_pilots_mirror.py` (the safety net for the refactor). `suggested_position_pct = |delta_i| / total_equity` still reproduces the order notional through `queue_builder`'s `notional = equity * pct` math for BOTH sides exactly as before. **Retention (Bug A fix, 2026-07):** the retention axis for a dropped-but-still-held name is HELD-NESS, not `queue_written`/mode — `queue_written` is `False` in the default `off` mode on every call, so gating retention on it meant a computed force-exit was shown only in that one call's ephemeral preview and then silently forgotten; a dropped name whose market value the follower still holds is now carried forward (unchanged) in `FollowsStore.set_mirrored`'s persisted set until it is actually no longer held, however that exit happened. `plan_follow(...)` computes the `planned_intents` preview via `build_follow_intents` (unchanged), then writes this Pilot's own source file (`execution.compose.write_follow_source`, using the SAME `prior_mirrored` read before persistence updates it) and calls `execution.compose.compose_and_emit(account_snapshot, extra_follow_pilot_ids=[pilot_id])` — replacing a direct `emit_execution_queue(FollowRunResult(...))` call, since that queue file is no longer this function's alone to write (see `execution/compose.py` above). Returns `{planned_intents, mode, queue_written}` — `queue_written` now answers "did the actual execution queue get written/updated," which may also reflect OTHER sources' claims, not only this Pilot's own, since composition is a union. **Broker quarantine intact** — no new order code; NO `place_*`/`submit_order`/`*_order` symbols (keeps `tests/test_pipeline_smoke.py::TestNoOrderFunctions` green); all real safety (`PreTradeRiskGate`, `GlobalKillSwitch`, `allow_place = mode=="live" AND …`) is reused verbatim, and the `robinhood-execution` skill remains the only actor that previews/places with per-trade human confirmation, paper-first. **D3 decision:** intent conviction = the pilot's normalized target weight (honest proxy, never inflated) and `min_conviction=0.0` so a deliberate Follow keeps every chosen name. Tests: `tests/test_pilots_{catalog,scoring,performance,follows,mirror}.py`. **`pilots/strategy_matrix.py`** — dependency-light reader (imports only `settings` + stdlib, never `signals` — see the module's own docstring for why an `import signals` here would defeat the `api/pilots_api.py` AST heavy-engine guard) assembling `GET /strategy/matrix`'s signal-module weight/enablement matrix from `settings.SIGNAL_WEIGHTS` + the persisted snapshot. `strategy_matrix()`'s return also carries a `meta_label` field — `_meta_label_distribution(snapshot)`'s portfolio-wide distribution of `meta_label_composite` across every symbol (fixed 20 bins over `[0, 1]`, `count`/`missing`/`n_gated`/`all_unity`/`min`/`max`/`min_confidence` — ports `gui/panels/strategy_matrix.py::_render_meta_label_distribution`). `all_unity: true` (every symbol at exactly 1.0) is the honest, EXPECTED state pre-Stage-4 — no MetaLabelers are registered in `ml.meta_labeling.global_meta_registry`, so `meta_label_proba` defaults to 1.0 (a multiplicative no-op) for every module; `n_gated` counts a genuine `0.0` (a real hard gate), never conflating it with the fabricated-1.0 bug the legacy panel's own `or 1.0` coercion had (fixed at the source — see `reporting/state_snapshot.py` below). **`pilots/symbols.py`**'s `symbol_detail()` carries a `sizing` group (`kelly_target_pre_regime`/`kelly_target_post_regime`/`regime_multiplier`/`meta_label_composite`/`max_position_weight`) — the pre/post-regime Kelly Target breakdown ports `gui/panels/strategy_matrix.py::_render_regime_multiplier_impact` onto `SymbolDetail.tsx`, reusing the SAME `signals[]` entry (no recomputation, no engine import); `compare_symbols()` gains the same two fields for free once populated. Both readers' sizing/meta-label fields are sourced from `strategy_engine.py::evaluate_security()`'s `Meta_Label_Composite`/`Regime_Multiplier`/`Kelly_Target_Pre_Regime`/`Kelly_Target_Post_Regime`, threaded through `pipeline/production_steps.py`'s `eval_results` + column-projection loop as deliberately non-`COLUMN_SCHEMA` `dashboard_df` columns (mirrors the pre-existing `Score_Components` pattern — pandera is `strict=False`, `sheet_publisher`'s header-projection filters them out, so zero Sheets/DB-migration blast radius) and read by BOTH `main_orchestrator._write_state_snapshot` and `reporting/state_snapshot.py`'s advisory writer via the shared `_safe_float_or_none` coercer (NaN/absent → JSON `null`, a genuine `0.0` preserved — CONSTRAINT #4). Tests: `tests/test_pilots_strategy_matrix.py`, `tests/test_pilots_symbols.py`, `tests/test_state_snapshot_parity.py`, `tests/test_orchestrator_e2e.py::TestStateSnapshot::test_sizing_decomposition_populated_via_real_run_pipeline`.
- **api/pilots_api.py** — **NEW FastAPI app** (`uvicorn api.pilots_api:app --port 8602`) serving the Pilots PWA. A SEPARATE app from `state_api.py`/`control_api.py` (its follow write-path needs `execution` imports that `state_api.py`'s AST guard forbids). Copies `state_api.py`'s auth/CORS pattern. **Read endpoints** (fail-open `require_read_token` on `STATE_API_TOKEN`; `/health` always open): `GET /health`; `GET /pilots` (list + `headline` metrics via `pilots.performance.pilot_headline` + `aum_proxy`/`followers_proxy` + `holdings_count`; never 404s, `0`/`None` on cold start); `GET /pilots/{id}` (detail: holdings + `sector_allocation` + headline + `recent_trades` + `as_of`; 404 unknown id; cold-start returns empty collections + honest `reason`, never fabricated); `GET /pilots/{id}/performance?range=1W|1M|3M|6M|1Y|2Y` (422 bad range; `curve` is the real downsampled base-100 OOS equity series persisted by `validation/harness.py`, tail-sliced to `range` — `null` + honest `reason` only when the Pilot has no backtest or the summary predates that field, never synthesized); `GET /pilots/{id}/holdings`; `GET /pilots/{id}/trades?limit=`; `GET /portfolio` (serializes `data.historical_store.HistoricalStore.latest_account_snapshot()` → `AccountSnapshot.to_dict()` + `is_stale`/`age_hours`, **honest 404** on cold DB, read-only/DB-first/no Robinhood login, wrapped so a cold DB never 500s); `GET /portfolio/equity-curve?range=` (from `account_snapshot_history()`). **Follow endpoints** (**FAIL-CLOSED** `require_command_token` on `settings.FOLLOW_API_TOKEN` — unset ⇒ 403 disabled, mirroring `control_api`): `GET /follows`; `PUT /follows {pilot_id, amount}` (upsert/cancel, 404 unknown pilot); `POST /pilots/{id}/follow {amount>0}` (404 unknown → 423 kill-switch-active → persist follow → `pilots.mirror.plan_follow` → `{follow, planned_intents, mode, queue_written}`; no account snapshot ⇒ preview-only with honest `note`, never fabricated equity). CORS mirrors `state_api` + `POST`/`PUT`; tokens use `hmac.compare_digest`, NEVER logged. **Brokerage-connect endpoints (2026-07; rebuilt 2026-08 for async device-approval login):** `GET /brokerage/status` (fail-open `require_read_token`, NOT flag-gated — reads `data.brokerage_credentials.rh_credentials_present()` + a DB account-snapshot check + the live `settings.ROBINHOOD_AUTO_REFRESH_ENABLED` value as `auto_refresh_enabled`, all dead-letter safe, never returns credential values). `POST /brokerage/connect` and `POST /brokerage/refresh` no longer block on a synchronous login — Robinhood's device-approval push can take anywhere from a few seconds up to the full login deadline, far too long to hold an HTTP request open, and a real login can only safely happen inside the isolated killable worker described in `docs/architecture/data-layer.md` (`data/robinhood_login.py`/`data/robinhood_login_worker.py`). Both now return **202** immediately with a job's initial status via `api._rh_login.start_connect_job`/`start_refresh_job` + `serialize_job` — `{job_id, mode, state, phase, error_code, seconds_remaining, connected, has_account_snapshot}`. `BrokerageConnectRequest` no longer has an `mfa_code` field (device-approval needs no code from the user). Gating is UNCHANGED: `connect`/`disconnect` behind `require_brokerage_connect_enabled` (fail-closed on `settings.BROKERAGE_CONNECT_ENABLED`, default `False`) + `require_command_token` + `require_loopback`; `refresh` behind its own DEDICATED `require_brokerage_refresh_enabled` (`settings.BROKERAGE_REFRESH_ENABLED`) + the same command-token + loopback pair — connect intake being disabled must never block refreshing already-configured credentials. `GET /brokerage/login/status/{job_id}` (new; `require_read_token` + `require_loopback`) polls a job to a terminal state — 404 if unknown. `POST /brokerage/login/cancel/{job_id}` (new; `require_command_token` + `require_loopback`) SIGTERM→SIGKILLs the worker process group; reports `cancelled: false` honestly if the kill couldn't be confirmed rather than claiming success it didn't achieve, mirroring `api/_jobs.py::cancel_job`'s posture. Credential PERSISTENCE (`data.brokerage_credentials.write_rh_credentials`) happens exactly once, in a background watcher thread inside `api/_rh_login.start_connect_job` — the moment (and only if) the job reaches `state="succeeded"` — never in either request handler, never before verification succeeds, and independent of whether a client keeps polling after it has already seen "succeeded" once (see `tests/test_rh_login_api_glue.py`). `disconnect_brokerage` is unchanged: best-effort logs out (`robinhood_portfolio.logout()`, failure swallowed) then unconditionally clears credentials. Credential values are never logged, cached, or echoed back in any response (CONSTRAINT #3). **AST-guard invariant** (like `state_api.py`): never imports the heavy calculation engines (`processing_engine`/`strategy_engine`/`forecasting_engine`/`macro_engine`/`technical_options_engine`/`main_orchestrator`) — it reaches the execution write-path only transitively through `pilots.mirror`; `pilots.*`, `execution.kill_switch`, `data.historical_store`, `data.robinhood_portfolio`, `data.brokerage_credentials`, `data.robinhood_login` (2026-08, new — the killable-subprocess login-job launcher; imports only stdlib + `settings`, no heavier than `gui.orchestrator_runner`, which this module's `POST /jobs`-adjacent pattern deliberately mirrors), `api._rh_login` (2026-08, new — the thin glue module), `gui.ai_control_center`, `llm.status_store` ARE allowed. **LLM diagnostics endpoint (2026-07, new):** `GET /llm/status` (fail-open `require_read_token`, deliberately **NOT** gated by `LLM_COMMENTARY_ENABLED`/`OPAL_RESEARCH_ENABLED`/`GRAVITY_AI_RUNNER_ENABLED` — mirrors `/brokerage/status`'s "a status endpoint REPORTS config, it does not enforce it" posture: the whole point is to be readable precisely WHEN a feature is off and the operator is working out why the narratives are null) returns per-capability config rows (`gui.ai_control_center.control_center_overview`) joined with per-provider last-real-call telemetry (`llm.status_store.read_all`, keyed `claude`/`gemini`/`openai`), a server-computed `attention` bool + `attention_reason` token (`"invalid_key"|"missing_key"|null`), and every field's `*_source` named.
