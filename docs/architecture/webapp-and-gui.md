- **Background job execution (`api/_jobs.py`, `api/control_api.py`'s `POST /jobs`/`GET /jobs/{id}`/`POST /jobs/{id}/cancel`/`GET /jobs/{id}/stream`, PR #487)** — a closed-enum background-process runner previously undocumented here: `JobType` dispatches to one hardcoded-argv `launch_*` function in `gui/orchestrator_runner.py` per type, gated by `settings.JOBS_API_ENABLED` (master switch) + the same fail-closed `ORCHESTRATOR_DAEMON_TOKEN` command token as `POST /run`. Backs the `Console.tsx` screen's one-click Preflight/Pytest/Advisory/Verify/Gravity-Audit/Backtest buttons (`createJob`/`getJobStatus`/`cancelJob` in `src/api/client.ts`, live output via `<LogStream>`'s SSE stream). Cancellation (`POST /jobs/{id}/cancel`) guards against completed jobs, reporting `cancelled: false` honestly without overwriting terminal exit status (`success`/`failed`), and `Console.tsx` renders `"—"` for non-running jobs. **`JobManager.cancel_job()` uses `gui/orchestrator_runner.py::stop_run_detailed()` (2026-08 fix), not the plain bool-returning `stop_run()`** — the underlying `stop_run()` conflates "the process was already dead when we looked" with "we just killed it" into the same bare `True` (documented in its own docstring's "or was never running" clause), and a `cancel_job()` built on a separate `is_running()` pre-check plus that bool left a real, if narrow, race: a process racing to ANY exit code (not just the `rc==0` case an earlier fix caught) between the check and the kill attempt could still get mislabeled `"cancelled"`. `stop_run_detailed()` returns a `StopOutcome(stopped, already_stopped)` from ONE atomic-as-possible liveness+kill attempt (no separate pre-check), so `cancel_job()` can tell "it finished on its own" (any exit code) apart from "an earlier call already cancelled it" and never flips `rec.cancelled` in either case — the double-cancel case correctly reports `cancelled: true` (it WAS cancelled, just not by this call) instead of a misleading "could not be confirmed". `stop_run()` itself is kept as a thin backward-compatible wrapper over `stop_run_detailed()` for its other callers (`gui/panels/ai_control_center.py`, `gui/panels/launcher.py`, `desktop/engine_supervisor.py`), which still only need "stopped or not". Tests: `tests/test_control_api.py::TestJobsApi` (`test_double_cancel_running_job_returns_true_and_preserves_cancelled`, `test_cancel_race_with_natural_completion_returns_false_and_preserves_status[rc=0,1]`). **`Console.tsx` is routed at `/console` and, as of PR #511 (`8083b5ae`, 2026-07-31), has a `NAV_ITEMS` entry** (operations section, "Console" 🖥️) — no longer direct-URL-only. **Command execution from the Commands screen (`settings.COMMAND_EXECUTION_ENABLED`, 2026-07, new)** extends this same job runner with a `JobType.COMMAND` value: `webapp/src/screens/Commands.tsx` (previously strictly compose/copy-only — see `commandParse.ts`'s doc comment) gained a `RunCommandControl` that calls `createJob("command", {command, subcommand, args, confirm})`, reusing the identical create/poll/cancel/`<LogStream>` plumbing. The server resolves `command`/`subcommand` against the SAME committed `cli_introspect/command_manifest.json` artifact `GET /commands` already serves (`pilots.commands.resolve_command` — never a client-supplied path/module string) and `gui/orchestrator_runner.py::launch_manifest_command` builds argv from the resolved `CommandSpec.invocation` plus the caller's `args`. `app_shell.py` stays copy-only (`DISALLOWED_EXECUTE_COMMANDS` — it pops a native window on the server host, not the browser); `execution.kill_switch --activate`/`--deactivate` and `main.py --refresh-account` require an explicit `confirm=true` (surfaced client-side as a `Modal` confirmation dialog via `commandParse.ts`'s `highStakesReason`, re-enforced server-side in `HIGH_STAKES_COMMANDS`) — see `CLAUDE.md`'s `COMMAND_EXECUTION_ENABLED` bullet for the full gating chain. Tests: `tests/test_command_execution.py`, `tests/test_pilots_commands.py`, `webapp/src/screens/Commands.test.tsx`.

- **api/data_api.py** — **STANDALONE FastAPI service** (`uvicorn api.data_api:app --port 8603`) exposing data-ingestion, market-data, and universe endpoints consumed by the Pilots PWA's `/data/*` routes. Unlike the light, AST-guarded `api/pilots_api.py` (whose read-only purity is statically enforced against importing the heavy calculation engines — see `docs/architecture/observability-and-apis.md`), this module MAY freely import the engine/data layer — it is a data-facing service, not the kill-switch/daemon control plane, and carries no AST guard. **Auth** mirrors `api/state_api.py`: a fail-open bearer token (`require_token`, `settings.STATE_API_TOKEN`, constant-time compare via `hmac.compare_digest`, 401 on mismatch) applied to every endpoint except `/health` (always open). **Honesty (CONSTRAINT #4):** `_clean_nan()` recursively converts NaN/inf floats to `null` before every response — never a fabricated `0.0`. **Existing endpoints:** `GET /data/bars/{symbol}` (daily OHLCV via `HistoricalStore`, `[]` on none);
