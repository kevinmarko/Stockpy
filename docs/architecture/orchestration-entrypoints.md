- **engine/__init__.py** — Package marker for the `engine/` advisory and orchestration layer.
- **engine/advisory.py** — Holding-aware per-symbol advisory engine. Public API: `evaluate(symbol, position, market, snapshot, macro_dto=None, transactions_store=None) -> Recommendation`. `Recommendation` is a frozen dataclass: `symbol`, `action: Literal["BUY","SELL","HOLD"]`, `strategy: str`, `conviction: float`, `rationale: str`, `suggested_position_pct: float`, `forecast: float|None`, `key_indicators: dict[str,float]`, `data_quality: Literal["OK","STALE","PARTIAL"]`. All 16 CONFIG thresholds (score gates, P&L thresholds, dividend bias rule, Kelly params, conviction levels, forecast direction threshold) live in a single `CONFIG` dict at module top — no magic numbers in the decision logic. Pipeline (each stage in try/except for dead-letter resilience): (1) live quote + OHLCV bars via `MarketDataProvider`; (2) `MarketBarDTO` construction; (3) fundamentals + `FundamentalDataDTO`; (4) `ProcessingEngine` technical metrics; (5) `volatility.garch.GarchVolatilityEstimator` GJR-GARCH vol (was `TechnicalOptionsEngine` until 2026-09, step 3d); (6) `ForecastingEngine` 30-day blended forecast; (7) neutral `MacroEconomicDTO` default when not injected; (8) `StrategyEngine.evaluate_security()` for raw signal + score; (9) **Holding-aware overlay** — three mutually-exclusive cases: *Case A* (below effective cost + bearish forecast → SELL escalation, elevated conviction), *Case B* (**DIVIDEND HOLD BIAS RULE**: `dividend_yield ≥ 4%` OR `dividends_received ≥ $50` AND score < `buy_score_threshold` → HOLD override, dividends cited in rationale), *Case C* (unrealized gain ≥ 10% + non-bearish forecast → HOLD instead of BUY). (10) fractional-Kelly sizing via `sizing.kelly` / `sizing.vol_target` (fallback when < 30 trades), clamped to `CONFIG["max_single_position_pct"]` (default 5%); (11) one-paragraph plain-English rationale citing top 2-3 drivers; (12) `key_indicators` dict with NaN for unavailable values; (13) `data_quality` = PARTIAL (any module failure) > STALE (quote.is_stale) > OK. **Soft macro gate defense-in-depth (2026-08 follow-up to the macro-killswitch fail-open fix)**: the macro-triggered gating step's soft gate (VIX > threshold OR Sahm ≥ threshold → score penalty, distinct from the hard `market_regime in ("RECESSION", "CREDIT EVENT")` gate a few lines above it) now also fires on `macro_dto.data_unavailable` directly, mirroring the same pattern `execution/risk_gate.py::stress_scenario_check` already applies independently of `killSwitch`. Traced to be currently unreachable in practice — `dto_models.py::_rules_based_regime` forces `market_regime` to `"RECESSION"` unconditionally whenever `data_unavailable=True`, so the hard gate immediately above always fires first in that state — but kept as an explicit, independent check so a future change to the `if`/`elif` coupling can't silently let a fabricated VIX/Sahm reading read as real "not stressed" data for this softer gate. See `docs/known_issues/macro_killswitch_fail_open_on_missing_fred_data.md`'s "Follow-up fix" section. **Source-of-truth rules** (CONSTRAINT #4): `PortfolioPosition`/`AccountSnapshot` (Robinhood) are the source of truth for cost basis, qty, and dividends; `MarketDataProvider` is the source of truth for prices, bars, and fundamentals — these roles never cross. Heavy engines imported at module level (not lazily) so `mock.patch("engine.advisory.<ClassName>")` resolves correctly in tests. **Engine DI + singletons (2026-07, PR A hot-path)**: `evaluate()` no longer reconstructs its heavy engines per symbol — `ProcessingEngine`, `GarchVolatilityEstimator` (formerly `TechnicalOptionsEngine`), `ForecastingEngine`, `StrategyEngine`, and ONE `TransactionsStore` are now lazily-built module-level singletons (`_get_processing_engine()` / `_get_garch_estimator()` / `_get_forecasting_engine()` / `_get_strategy_engine(store)` / `_get_transactions_store()`, guarded by a double-checked `_ENGINE_LOCK` `threading.Lock`), and `evaluate()` gained optional kw-only injection params (`processing_engine` / `garch_estimator` (renamed from `technical_options_engine` in step 3d) / `forecasting_engine` / `strategy_engine`) so orchestrator callers can pass their already-built `EngineContext` engines. The single `TransactionsStore` (`transactions_store` arg if supplied, else the singleton) is threaded through all former per-call `TransactionsStore()` sites (StrategyEngine ctor, Kelly sizing, verbose path) instead of each building its own (which did `create_all`+`inspect`+`ALTER` 2–3× per symbol). Singletons are stateless/read-only here → identical output; `TransactionsStore`'s per-call SQLAlchemy sessions and the engines are safe to share across the orchestrator's now-parallelized advisory loop. `mock.patch` is preserved by comparing the module global against the import-time class and building a fresh (uncached) instance when patched. **Pipeline-compute reuse (2026-07, PR D, OUTPUT-CHANGING opt-in via `settings.ADVISORY_REUSE_PIPELINE_COMPUTE`, default `False`)**: `evaluate()` gained keyword-only `precomputed_garch`/`precomputed_forecast: Optional[float] = None`. When `main_orchestrator.py`'s advisory overlay (run AFTER `run_pipeline()` has already GJR-GARCH-fit and forecast-fit every ticker once this cycle) supplies a real positive value — sourced from that SAME cycle's `dashboard_df['GARCH_Vol']` / `dashboard_df['Forecast_30']` for the ticker — Step 5 / Step 6 skip their fit entirely and use the supplied value verbatim, eliminating the single largest redundant per-cycle CPU cost (GARCH MLE fit + the full ARIMA/Holt-Winters/CNN-LSTM/Prophet ensemble, run twice per ticker per cycle pre-PR-D). A missing/`None`/zero/non-positive value transparently falls through to the original independent fit (CONSTRAINT #6: can only ever REMOVE a redundant fit, never silently substitute a bad one). **`StrategyEngine.evaluate_security()` (Step 8) is deliberately NEVER skipped by this flag** — a pre-existing gap was found during PR D's design: `main_orchestrator.py`'s OWN `run_pipeline()` strategy loop calls `evaluate_security()` WITHOUT `context_extras` (unlike `advisory.evaluate()`'s own call, which always threads `context_extras` for cross-sectional-momentum/multifactor scoring), so reusing `run_pipeline`'s `strategy_output` would have silently zeroed those signal contributions in every advisory recommendation; PR D therefore scoped the dedup to GARCH/forecast only and left this gap flagged (out of scope) rather than silently papering over it. Because an independent fit and a reused one are not guaranteed bit-identical (CNN-LSTM's random weight init, GARCH's numerical optimizer), enabling this flag can move `Advisory_*` column values slightly — unlike PR A's byte-identical hot-path changes, this is why it has its own opt-in flag defaulting `False`. `main_orchestrator.py`'s `_eval_one` closure threads `precomputed_garch=_row.get('GARCH_Vol')` / `precomputed_forecast=_row.get('Forecast_30')` only when the flag is on; `None`/`None` otherwise (reproducing pre-dedup behavior exactly). **New env var**: `ADVISORY_REUSE_PIPELINE_COMPUTE` (bool, default `False`), GUI-writable (`shared/env_io.py` `ALLOWED_KEYS` + Settings Manager). **HistoricalStore routing (Steps 1 & 3)**: `evaluate()` gained an optional kw-only `historical_store: Optional[Any] = None` param and a matching lazy `_get_historical_store()` module singleton (same pattern as the other engine getters). When `settings.HISTORICAL_STORE_ENABLED`, Step 1's bars fetch routes through `HistoricalStore.get_bars(symbol, lookback_days=252, provider=market)` and Step 3's fundamentals fetch routes through the new `HistoricalStore.get_fundamentals_raw(symbol, max_age_days=settings.FUNDAMENTALS_REFRESH_DAYS, provider=market)` — closing the gap where this per-symbol loop (the highest-frequency data-fetch site in the platform) bypassed the DB even though `pipeline/advisory_inputs.py::fetch_bars_for_universe` had already DB-cached the same bars moments earlier in the same cycle. Both fall back to the direct `market.get_intraday_bars`/`market.get_fundamentals` call on any `HistoricalStore` failure or when the flag is off. **Important dead-letter interaction**: because `HistoricalStore` is itself dead-letter safe (a provider failure inside it degrades to an empty result rather than raising), an EMPTY result from either method is re-derived via an unguarded direct provider call rather than treated as success — this preserves the pre-existing rule that `data_quality=PARTIAL` is set only on a genuine fetch exception, never on legitimately-empty data.
- **`.env` loading convention (CRITICAL — read this before touching any entry point; rewritten 2026-08 after a real `.env`-resolution bug)** — `settings.ENV_PATH` (`Path(__file__).resolve().parent / ".env"`, defined in `settings.py`) is now the SINGLE anchor every `.env` locator in the codebase imports rather than re-deriving. Before this fix, three independent locators disagreed: pydantic-settings' own `env_file=".env"` (CWD-relative), a bare `load_dotenv()` (uses `find_dotenv()`, which walks UP from the calling file's directory — in a git worktree with no `.env` of its own, this silently found a PARENT checkout's `.env`), and `shared/env_io.py`/`data/brokerage_credentials.py`'s own independently-derived repo-root paths — an operator hit this as a spurious `RH_USERNAME missing` error despite a fully-populated `.env`. Every `.env`-loading call site now passes `ENV_PATH` explicitly: `main_orchestrator.py` calls it inside `async def main()`; `desktop/orchestrator_daemon.py::run_forever()` calls it (deferred import, matching the file's own side-effect-free-on-import convention) before starting its servers; the five standalone `api/*.py` FastAPI services (`state_api.py`/`control_api.py`/`data_api.py`/`metrics_api.py`/`pilots_api.py` — previously the ONLY callers with no `main()`-style entry point to hook this into at all, so a standalone `uvicorn api.X:app` never loaded `.env`) now call it at true module top, before any subsequent project import; every `scripts/*.py` entry point calls it via the new `scripts/_bootstrap.py::bootstrap()` (see that module's own docstring for placement rules — module top vs. inside `if __name__ == "__main__":`, split by whether the script is ever imported as a library elsewhere). Library-style helpers (e.g. `pipeline/advisory_inputs.py`) deliberately do NOT call it — direct callers that bypass the entry points (`make verify`, `verify.command`, ad-hoc REPL) call `load_dotenv()` themselves in their own wrappers. **Credential reads no longer need this at all, for the modules that were fixed**: `data/robinhood_portfolio.py`'s `_require_setting` (renamed from `_require_env`) and `data/brokerage_credentials.py`'s credential functions now read via `settings.settings.X` — which loads `.env` independently through pydantic-settings' own `env_file=ENV_PATH` mechanism and needs no `load_dotenv()` call to see a value — rather than `os.environ.get(...)`, which pydantic-settings never populates. `load_dotenv()` remains necessary for the smaller set of call sites that still read raw `os.environ.get(...)` for a value with no `settings.py` field. **Why the call lives inside the function, not at module top, for `main_orchestrator.py` specifically?** Module-top invocation pollutes the pytest session: importing it would load every `.env` value into `os.environ`, breaking `tests/test_settings.py::test_settings_defaults` (which asserts unset defaults for a clean-environment Settings()). `override=False` so an explicit shell `export` always wins over `.env`. Regression test: `tests/test_env_loading.py` AST-walks both entry points to assert a `load_dotenv()` call exists *somewhere* in the file (module top OR inside any function body) — any future refactor that removes it entirely fails CI immediately; `tests/test_scripts_bootstrap.py` provides the equivalent static guard for every `scripts/*.py` file's `bootstrap()` call. The empty-universe warning in the universe builder names the three remediation paths (RH_* env vars / WATCHLIST env var / watchlist.txt) so the operator can act without spelunking through the source. **(2026-09, step 4e)**: the Google Sheet Sheet2-column-A last-resort fallback this warning used to also name was retired to `legacy/` along with the rest of the Sheet publisher — see the archived `main.py` bullet below.
- **alerting.py** — Structured logging setup and push-notification dispatcher. Three public functions: `setup_logging(log_level="INFO")` — idempotent root-logger configuration: `RotatingFileHandler` writing to `investyo.log` under `settings.LOCAL_DATA_ROOT / "logs"` (default `~/.stockpy_local/logs`, entirely outside every git checkout/worktree — see `docs/architecture/data-layer.md`'s `settings.LOCAL_DATA_ROOT` subsection for the full layout; 10 MB × 5 backups, UTF-8) + `StreamHandler` to stderr, both using the timestamp/level/module/message formatter; safe to call multiple times. `notify(title, message, priority="default")` — POSTs to `https://ntfy.sh/{NTFY_TOPIC}` using `urllib.request` (stdlib, no new dependency); no-op when `NTFY_TOPIC` is unset; network failures caught and logged as WARNING, never propagated; secrets MUST NOT appear in title/message. `summarize_run(result)` — duck-typed on `RunResult`'s attributes (`recommendations`, `errors`, `started_at`, `duration_seconds`) to avoid circular import; returns a compact multi-line string with symbol counts, BUY/SELL/HOLD tallies, error count, elapsed time, and the top 3 highest-conviction actionable recommendations. Integration in the daemon path: `setup_logging()` is called at startup; after each cycle `summarize_run()` is logged at INFO; the clean-run "refresh complete" push fires at most once per ET day and any symbol-level error triggers a `priority="high"` ntfy push listing the failing symbols and stages (the archived `main.py` used a `_clean_notified` flag per launch). New env var: `NTFY_TOPIC` (unset = no-op).
- **Makefile** — Developer convenience targets: `make verify` (env-var check → pytest → one standalone dry-run cycle via `scripts/step5_4_verify_cycle.py` + print summary; replaced the old `run_once()` step), `make test` (pytest only), `make smoke` (pipeline smoke tests only). All targets use `.venv/bin/python3`.
- **verify.command** — macOS double-click readiness gate (same steps as `make verify`): (1) env-var presence check (FRED_API_KEY required; Robinhood/ntfy optional); (2) full pytest suite — aborts if any test fails; (3) one standalone dry-run pipeline cycle (its own process; it never contacts the daemon) through `scripts/step5_4_verify_cycle.py` (`asyncio.run(main_orchestrator.main(dry_run=True, strict=False))`) with, for that process only, `DAEMON_AGENTIC_QUEUE_MODE` forced `off`, symbol-rating and cap-audit recording off, the Robinhood account fetch restricted to its cache (never a device-approval login), no heartbeat file, and every alert (including the end-of-cycle summary) suppressed, so it writes no queue and sends no pushes or orders; it still fetches live market data and rewrites `state_snapshot.json`, the dashboards and `dead_letter.json`. A failed cycle (exit 1), one that did not refresh the snapshot (exit 3) or one that ran on synthetic `MockDataEngine` data or produced no signals (exit 4) fails the gate. Equivalent to `make verify` but opens in a Terminal window from Finder or the Dock. Make executable once with `chmod +x verify.command`.

- **`_build_universe` — recently-closed-position retention (2026-08)**: `_build_universe` gained a 6th source, `recently_closed_universe_symbols(held)` (`pipeline/advisory_inputs.py`), unioned in LAST -- after both the rating-exclusion subtraction and the `DEFAULT_TICKERS` empty-fallback decision (both now live inside `data.portfolio_sync.compute_tracked_universe()`; the Sheet2 fallback the archived `main.py` bullet above used to also mention here was retired in step 4e, 2026-09). - **main_orchestrator.py** — newer async master orchestrator. Pipeline: (1) async data fetch, (2) `run_pipeline()` (macro → trend & volatility → processing → forecasting → strategy; the options step was split into `MacroStep` + `TrendVolatilityStep` and the 0DTE/options-lifecycle hooks removed in 2026-09, step 3d), (3) the advisory overlay (`AdvisoryOverlayStep`, split out of `BrokerExecutionStep` in step 5.2: `engine.advisory.evaluate()` per universe symbol with the shared `build_context_extras` extras, keeping `ctx.recommendations`), (4) the agentic queue (`AgenticQueueStep`, `settings.DAEMON_AGENTIC_QUEUE_MODE`, default `off`; `shadow` writes the Robinhood queue under `OUTPUT_DIR/shadow/` only; `primary` (step 5.3; live since 2026-10-12) sends the summary push, runs the watch engine and writes the REAL queue with its side effects (the archived `main.py` used to do these and skipped them once the daemon owned them) -- see `execution.md`'s `compose.py` entries and `pipeline/agentic_queue.py`. `_main_body_impl` wraps the runner in a `finally` that calls `pipeline.agentic_queue.close_cycle_queue_writer(ctx.context_extras)`, so a timed-out `AgenticQueueStep` thread can no longer commit a queue file after its cycle ended; `StateSnapshotStep` passes `recommendations=` to `_write_state_snapshot` in primary, adding `garch_vol`/`suggested_exit_pct` per signal), (5) broker execution via `_execute_broker_orders()` (paper ledger only; none when going live), (6) state snapshot, HTML report + Plotly chart, JSON payload print, then schema validation. **Preflight Check (2026-07)**: Removed 2026-09-30: `main_orchestrator.main()` used to raise `PipelineFatalError` whenever `ADVISORY_ONLY=False` and Alpaca keys were missing; with Alpaca gone that trap is gone, and a going-live run simply places no automated orders (`resolve_broker_backend()` returns None, CRITICAL log + alert). New in Prompt 5.2: `main(dry_run=False)` wraps `_main_body()` in a try/finally that cancels a `_heartbeat()` asyncio background task. `_main_body()` is now a thin progress-instrumentation wrapper delegating to `_main_body_impl()` (the original cycle logic); the fatal-crash handler (`telemetry.critical(..., exc_info=True)` → `raise PipelineFatalError`) lives inside `_main_body_impl`. `_heartbeat(output_dir, interval=60)` logs `"ORCHESTRATOR ALIVE"` and writes `OUTPUT_DIR/heartbeat.txt` (UTC ISO timestamp) every 60 s so an external watchdog can detect crashes. `--dry-run` CLI flag: `python3 main_orchestrator.py --dry-run`. `_execute_broker_orders(final_df, dry_run, macro_dto)` translates BUY/SELL signals → `OrderIntent` → `OrderManager.submit_order_with_idempotency`; runs reconciliation before submission; logs CRITICAL on drift. Uses `resolve_broker_backend()`; places no orders when going live (`PAPER_TRADING=false`, `ADVISORY_ONLY=false`). **Persistent-daemon groundwork (2026-07):** `PipelineFatalError(RuntimeError)` is raised (never `sys.exit(1)`) on a fatal per-cycle failure (data-fetch crash, pipeline crash, or strict-mode schema-validation failure) so a long-lived caller (`desktop/daemon_runtime.py`) can catch it with a plain `except Exception`, record a FAILED run, and keep serving — the `__main__` block still converts it to `sys.exit(1)` so CI/`make verify`/the GUI subprocess see the original non-zero-exit contract. `EngineContext` (dataclass of optional pre-built engine instances: `macro_engine`, `garch_estimator` (replaced `technical_options_engine` + `iv_history_store` in step 3d), `processing_engine`, `forecasting_engine`, `strategy_engine`, `evaluation_engine`) + `EngineContext.build(data_engine=...)` let a persistent caller construct every heavy engine ONCE and reuse them across cycles instead of paying full import+init cost every run; `run_pipeline(..., engines: Optional[EngineContext] = None)` and `_main_body(..., engines=..., data_engine=...)` both default to `None` (today's exact per-call construction behavior) and reuse whatever's supplied — a partially-populated context falls back to constructing only the missing engines fresh. `_main_body`'s `data_engine` param, when supplied, also bypasses the live-data check (`data_engine.live_data_configured()`, a configured FRED key;
