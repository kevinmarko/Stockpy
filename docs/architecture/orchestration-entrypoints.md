# Architecture: Entry Points & Orchestration

> Part of the split-out `CLAUDE.md` System Architecture reference. See [../../CLAUDE.md](../../CLAUDE.md) for the index.

- **engine/__init__.py** — Package marker for the `engine/` advisory and orchestration layer.
- **engine/advisory.py** — Holding-aware per-symbol advisory engine. Public API: `evaluate(symbol, position, market, snapshot, macro_dto=None, transactions_store=None) -> Recommendation`. `Recommendation` is a frozen dataclass: `symbol`, `action: Literal["BUY","SELL","HOLD"]`, `strategy: str`, `conviction: float`, `rationale: str`, `suggested_position_pct: float`, `forecast: float|None`, `key_indicators: dict[str,float]`, `data_quality: Literal["OK","STALE","PARTIAL"]`. All 16 CONFIG thresholds (score gates, P&L thresholds, dividend bias rule, Kelly params, conviction levels, forecast direction threshold) live in a single `CONFIG` dict at module top — no magic numbers in the decision logic. Pipeline (each stage in try/except for dead-letter resilience): (1) live quote + OHLCV bars via `MarketDataProvider`; (2) `MarketBarDTO` construction; (3) fundamentals + `FundamentalDataDTO`; (4) `ProcessingEngine` technical metrics; (5) `TechnicalOptionsEngine` GJR-GARCH vol; (6) `ForecastingEngine` 30-day blended forecast; (7) neutral `MacroEconomicDTO` default when not injected; (8) `StrategyEngine.evaluate_security()` for raw signal + score; (9) **Holding-aware overlay** — three mutually-exclusive cases: *Case A* (below effective cost + bearish forecast → SELL escalation, elevated conviction), *Case B* (**DIVIDEND HOLD BIAS RULE**: `dividend_yield ≥ 4%` OR `dividends_received ≥ $50` AND score < `buy_score_threshold` → HOLD override, dividends cited in rationale), *Case C* (unrealized gain ≥ 10% + non-bearish forecast → HOLD instead of BUY). (10) fractional-Kelly sizing via `sizing.kelly` / `sizing.vol_target` (fallback when < 30 trades), clamped to `CONFIG["max_single_position_pct"]` (default 5%); (11) one-paragraph plain-English rationale citing top 2-3 drivers; (12) `key_indicators` dict with NaN for unavailable values; (13) `data_quality` = PARTIAL (any module failure) > STALE (quote.is_stale) > OK. **Soft macro gate defense-in-depth (2026-08 follow-up to the macro-killswitch fail-open fix)**: the macro-triggered gating step's soft gate (VIX > threshold OR Sahm ≥ threshold → score penalty, distinct from the hard `market_regime in ("RECESSION", "CREDIT EVENT")` gate a few lines above it) now also fires on `macro_dto.data_unavailable` directly, mirroring the same pattern `execution/risk_gate.py::stress_scenario_check` already applies independently of `killSwitch`. Traced to be currently unreachable in practice — `dto_models.py::_rules_based_regime` forces `market_regime` to `"RECESSION"` unconditionally whenever `data_unavailable=True`, so the hard gate immediately above always fires first in that state — but kept as an explicit, independent check so a future change to the `if`/`elif` coupling can't silently let a fabricated VIX/Sahm reading read as real "not stressed" data for this softer gate. See `docs/known_issues/macro_killswitch_fail_open_on_missing_fred_data.md`'s "Follow-up fix" section. **Source-of-truth rules** (CONSTRAINT #4): `PortfolioPosition`/`AccountSnapshot` (Robinhood) are the source of truth for cost basis, qty, and dividends; `MarketDataProvider` is the source of truth for prices, bars, and fundamentals — these roles never cross. Heavy engines imported at module level (not lazily) so `mock.patch("engine.advisory.<ClassName>")` resolves correctly in tests. **Engine DI + singletons (2026-07, PR A hot-path)**: `evaluate()` no longer reconstructs its heavy engines per symbol — `ProcessingEngine`, `TechnicalOptionsEngine`, `ForecastingEngine`, `StrategyEngine`, and ONE `TransactionsStore` are now lazily-built module-level singletons (`_get_processing_engine()` / `_get_technical_options_engine()` / `_get_forecasting_engine()` / `_get_strategy_engine(store)` / `_get_transactions_store()`, guarded by a double-checked `_ENGINE_LOCK` `threading.Lock`), and `evaluate()` gained optional kw-only injection params (`processing_engine` / `technical_options_engine` / `forecasting_engine` / `strategy_engine`) so orchestrator callers can pass their already-built `EngineContext` engines. The single `TransactionsStore` (`transactions_store` arg if supplied, else the singleton) is threaded through all former per-call `TransactionsStore()` sites (StrategyEngine ctor, Kelly sizing, verbose path) instead of each building its own (which did `create_all`+`inspect`+`ALTER` 2–3× per symbol). Singletons are stateless/read-only here → identical output; `TransactionsStore`'s per-call SQLAlchemy sessions and the engines are safe to share across the orchestrator's now-parallelized advisory loop. `mock.patch` is preserved by comparing the module global against the import-time class and building a fresh (uncached) instance when patched. **Pipeline-compute reuse (2026-07, PR D, OUTPUT-CHANGING opt-in via `settings.ADVISORY_REUSE_PIPELINE_COMPUTE`, default `False`)**: `evaluate()` gained keyword-only `precomputed_garch`/`precomputed_forecast: Optional[float] = None`. When `main_orchestrator.py`'s advisory overlay (run AFTER `run_pipeline()` has already GJR-GARCH-fit and forecast-fit every ticker once this cycle) supplies a real positive value — sourced from that SAME cycle's `dashboard_df['GARCH_Vol']` / `dashboard_df['Forecast_30']` for the ticker — Step 5 / Step 6 skip their fit entirely and use the supplied value verbatim, eliminating the single largest redundant per-cycle CPU cost (GARCH MLE fit + the full ARIMA/Holt-Winters/CNN-LSTM/Prophet ensemble, run twice per ticker per cycle pre-PR-D). A missing/`None`/zero/non-positive value transparently falls through to the original independent fit (CONSTRAINT #6: can only ever REMOVE a redundant fit, never silently substitute a bad one). **`StrategyEngine.evaluate_security()` (Step 8) is deliberately NEVER skipped by this flag** — a pre-existing gap was found during PR D's design: `main_orchestrator.py`'s OWN `run_pipeline()` strategy loop calls `evaluate_security()` WITHOUT `context_extras` (unlike `advisory.evaluate()`'s own call, which always threads `context_extras` for cross-sectional-momentum/multifactor scoring), so reusing `run_pipeline`'s `strategy_output` would have silently zeroed those signal contributions in every advisory recommendation; PR D therefore scoped the dedup to GARCH/forecast only and left this gap flagged (out of scope) rather than silently papering over it. Because an independent fit and a reused one are not guaranteed bit-identical (CNN-LSTM's random weight init, GARCH's numerical optimizer), enabling this flag can move `Advisory_*` column values slightly — unlike PR A's byte-identical hot-path changes, this is why it has its own opt-in flag defaulting `False`. `main_orchestrator.py`'s `_eval_one` closure threads `precomputed_garch=_row.get('GARCH_Vol')` / `precomputed_forecast=_row.get('Forecast_30')` only when the flag is on; `None`/`None` otherwise (reproducing pre-dedup behavior exactly). **New env var**: `ADVISORY_REUSE_PIPELINE_COMPUTE` (bool, default `False`), GUI-writable (`gui/env_io.py` `ALLOWED_KEYS` + Settings Manager). **HistoricalStore routing (Steps 1 & 3)**: `evaluate()` gained an optional kw-only `historical_store: Optional[Any] = None` param and a matching lazy `_get_historical_store()` module singleton (same pattern as the other engine getters). When `settings.HISTORICAL_STORE_ENABLED`, Step 1's bars fetch routes through `HistoricalStore.get_bars(symbol, lookback_days=252, provider=market)` and Step 3's fundamentals fetch routes through the new `HistoricalStore.get_fundamentals_raw(symbol, max_age_days=settings.FUNDAMENTALS_REFRESH_DAYS, provider=market)` — closing the gap where this per-symbol loop (the highest-frequency data-fetch site in the platform) bypassed the DB even though `main.py`'s `_fetch_bars_for_universe` had already DB-cached the same bars moments earlier in the same cycle. Both fall back to the direct `market.get_intraday_bars`/`market.get_fundamentals` call on any `HistoricalStore` failure or when the flag is off. **Important dead-letter interaction**: because `HistoricalStore` is itself dead-letter safe (a provider failure inside it degrades to an empty result rather than raising), an EMPTY result from either method is re-derived via an unguarded direct provider call rather than treated as success — this preserves the pre-existing rule that `data_quality=PARTIAL` is set only on a genuine fetch exception, never on legitimately-empty data.
- **`.env` loading convention (CRITICAL — read this before touching any entry point; rewritten 2026-08 after a real `.env`-resolution bug)** — `settings.ENV_PATH` (`Path(__file__).resolve().parent / ".env"`, defined in `settings.py`) is now the SINGLE anchor every `.env` locator in the codebase imports rather than re-deriving. Before this fix, three independent locators disagreed: pydantic-settings' own `env_file=".env"` (CWD-relative), a bare `load_dotenv()` (uses `find_dotenv()`, which walks UP from the calling file's directory — in a git worktree with no `.env` of its own, this silently found a PARENT checkout's `.env`), and `gui/env_io.py`/`data/brokerage_credentials.py`'s own independently-derived repo-root paths — an operator hit this as a spurious `RH_USERNAME missing` error despite a fully-populated `.env`. Every `.env`-loading call site now passes `ENV_PATH` explicitly: `main.py` calls `_load_dotenv(ENV_PATH, override=False)` as the first line of `main()`; `main_orchestrator.py` calls it inside `async def main()`; `app_shell.py` and `desktop/orchestrator_daemon.py::run_forever()` call it (deferred import, matching each file's own side-effect-free-on-import convention) before starting their respective servers; the five standalone `api/*.py` FastAPI services (`state_api.py`/`control_api.py`/`data_api.py`/`metrics_api.py`/`pilots_api.py` — previously the ONLY callers with no `main()`-style entry point to hook this into at all, so a standalone `uvicorn api.X:app` never loaded `.env`) now call it at true module top, before any subsequent project import; every `scripts/*.py` entry point calls it via the new `scripts/_bootstrap.py::bootstrap()` (see that module's own docstring for placement rules — module top vs. inside `if __name__ == "__main__":`, split by whether the script is ever imported as a library elsewhere). `run_once()` deliberately does NOT call it (its docstring says so) — direct callers that bypass `main()` (`make verify`, `verify.command`, ad-hoc REPL) call `load_dotenv()` themselves in their own wrappers before invoking `run_once()`, and both already do. **Credential reads no longer need this at all, for the modules that were fixed**: `data/robinhood_portfolio.py`'s `_require_setting` (renamed from `_require_env`) and `data/brokerage_credentials.py`'s credential functions now read via `settings.settings.X` — which loads `.env` independently through pydantic-settings' own `env_file=ENV_PATH` mechanism and needs no `load_dotenv()` call to see a value — rather than `os.environ.get(...)`, which pydantic-settings never populates. `load_dotenv()` remains necessary for the smaller set of call sites that still read raw `os.environ.get(...)` for a value with no `settings.py` field. **Why the call lives inside the function, not at module top, for `main.py`/`main_orchestrator.py` specifically?** Module-top invocation pollutes the pytest session: importing `main` would load every `.env` value into `os.environ`, breaking `tests/test_settings.py::test_settings_defaults` (which asserts `ALPACA_API_KEY is None` for a clean-environment Settings()). `override=False` so an explicit shell `export` always wins over `.env`. Regression test: `tests/test_env_loading.py` AST-walks both entry points to assert a `load_dotenv()` call exists *somewhere* in the file (module top OR inside any function body) — any future refactor that removes it entirely fails CI immediately; `tests/test_scripts_bootstrap.py` provides the equivalent static guard for every `scripts/*.py` file's `bootstrap()` call. The empty-universe warning in `main.run_once()` names all four remediation paths (RH_* env vars / WATCHLIST env var / watchlist.txt / Sheet2 column A) so the operator can act without spelunking through the source.
- **alerting.py** — Structured logging setup and push-notification dispatcher. Three public functions: `setup_logging(log_level="INFO")` — idempotent root-logger configuration: `RotatingFileHandler` writing to `investyo.log` under `settings.LOCAL_DATA_ROOT / "logs"` (default `~/.stockpy_local/logs`, entirely outside every git checkout/worktree — see `docs/architecture/data-layer.md`'s `settings.LOCAL_DATA_ROOT` subsection for the full layout; 10 MB × 5 backups, UTF-8) + `StreamHandler` to stderr, both using the timestamp/level/module/message formatter; safe to call multiple times. `notify(title, message, priority="default")` — POSTs to `https://ntfy.sh/{NTFY_TOPIC}` using `urllib.request` (stdlib, no new dependency); no-op when `NTFY_TOPIC` is unset; network failures caught and logged as WARNING, never propagated; secrets MUST NOT appear in title/message. `summarize_run(result)` — duck-typed on `RunResult`'s attributes (`recommendations`, `errors`, `started_at`, `duration_seconds`) to avoid circular import; returns a compact multi-line string with symbol counts, BUY/SELL/HOLD tallies, error count, elapsed time, and the top 3 highest-conviction actionable recommendations. Integration in `main.py`: `setup_logging()` is the first call in `main()`; after each `run_once()`, `summarize_run()` is logged at INFO; a `_clean_notified` flag ensures at most one "refresh complete" push per launch in `--interval` mode; any symbol-level error triggers a `priority="high"` ntfy push listing the failing symbols and stages. New env var: `NTFY_TOPIC` (unset = no-op).
- **Makefile** — Developer convenience targets: `make verify` (env-var check → pytest → one live `run_once()` + print summary), `make test` (pytest only), `make smoke` (pipeline smoke tests only). All targets use `.venv/bin/python3`.
- **verify.command** — macOS double-click readiness gate (same steps as `make verify`): (1) env-var presence check (FRED_API_KEY required; Robinhood/ntfy optional); (2) full pytest suite — aborts if any test fails; (3) one live `run_once()` cycle, prints `summarize_run()` output. Equivalent to `make verify` but opens in a Terminal window from Finder or the Dock. Make executable once with `chmod +x verify.command`.
- **main.py** — **Clean advisory orchestrator** (replaces the legacy engine-calling monolith). Implements a two-tier refresh cadence: (1) account tier — Robinhood snapshot via `data.robinhood_portfolio.fetch_account_snapshot()` fetched at most once/day (daily JSON cache); forced by `--refresh-account`. (2) market tier — prices, bars, indicators, forecasts refreshed on every `run_once()` call via `engine.advisory.evaluate()`. Key components: `RunResult` (frozen dataclass: `snapshot, recommendations: list[Recommendation], errors: list[dict], started_at, finished_at, duration_seconds`); `run_once(force_account=False) -> RunResult` — the single public pipeline function; `_build_universe(snapshot) -> list[str]` — held symbols ∪ watchlist (`WATCHLIST` env/`watchlist.txt`) ∪ discovered scan candidates, rating-excluded when `SYMBOL_RATING_AUTO_DROP_ENABLED`, falling back to `settings.DEFAULT_TICKERS` and then `_load_tickers_from_sheet2()` (Sheet2 column A) only when that whole union is empty — the union/exclusion/fallback core is delegated to `data.portfolio_sync.compute_tracked_universe()`/`load_env_watchlist()` (see that module's entry in `docs/architecture/data-layer.md`), shared with `pipeline/production_steps.py::AsyncDataFetchStep` (the daemon path below) so the two can no longer silently diverge on what counts as "the tracked universe" — see `docs/known_issues/daemon_universe_watchlist_divergence.md` for the incident this closed; `_build_macro_dto() -> MacroEconomicDTO` — FRED fetch with neutral defaults fallback; `_fetch_bars_for_universe()` + `_build_context_extras()` — pre-compute xsec ranks + multifactor composites once before the per-symbol loop; `_write_to_sheet(result, market)` — maps `list[Recommendation]` to `config.COLUMN_SCHEMA` columns, preserves full conditional formatting; `_write_html_report(result, macro_dto)` — now routes through `reporting/html_publisher.py::write_html_report` (which in turn calls `diagnostics_and_visuals.generate_html_report`); `main()` — argparse with `--interval N` (loop every N seconds, account re-fetched at most once/day) and `--refresh-account`. Dead-letter pattern: per-symbol failures append to `RunResult.errors` and never abort the run. New env var: `WATCHLIST` (comma-separated ticker list; file alternative: `watchlist.txt`).
- **`_build_universe` — recently-closed-position retention (2026-08)**: `_build_universe` gained a 6th source, `_recently_closed_universe_symbols(held)` (`main.py`), unioned in LAST -- after both the rating-exclusion subtraction and the `DEFAULT_TICKERS`/Sheet2 empty-fallback decision (both now live inside `data.portfolio_sync.compute_tracked_universe()`/the Sheet2 branch, per the `main.py` bullet above). Placement is deliberate: a retained symbol has `held=False`, so unioning it before the auto-drop subtraction would let it be immediately re-subtracted (reproducing the "sold symbol silently disappears" bug this feature exists to fix, through a different door); unioning it before the empty-fallback check would silently suppress `DEFAULT_TICKERS`/Sheet2 on an otherwise-cold account. Reads `settings.CLOSED_POSITION_RETENTION_DAYS` (default 180 -- a deliberate behavior change; `0` restores the pre-2026-08 universe exactly) and `settings.CLOSED_POSITION_RETENTION_MAX_SYMBOLS` (default 25, bounding the added per-cycle pipeline cost) via `data.broker_fills_store.recently_closed_symbols()`, keyed off the operator's real Robinhood SELL fills (`data/broker_fills_store.py`) -- not internal paper trades. Fails open: any store error leaves the universe unaffected (CONSTRAINT #6). `data.portfolio_sync.build_sync_report()`/`resolve_universe()` carry the identical retention logic for the webapp/sync path via a synthetic `"closed:recent"` watchlist (`data.portfolio_sync.CLOSED_RECENT_LIST_KEY`) -- `resolve_universe()` additionally widens its auto-drop protected set to include that synthetic list (unlike `main.py`, its `tracked` set is built from `report.symbols.keys()` *before* the auto-drop subtraction, so the trap reappears there without an explicit fix). `async_sync_now()`'s `DEFAULT_TICKERS` persist deliberately EXCLUDES the synthetic list's symbols -- `DEFAULT_TICKERS` never expires and `resolve_universe()` unions it in unconditionally, so persisting a retained symbol there would silently convert a bounded retention window into a permanent universe addition, surviving even after retention is later disabled. `main_orchestrator.py` needs no equivalent change -- its `build_universe_fn` always receives a pre-resolved ticker list. See `data/broker_fills_store.py`'s entry in `docs/architecture/data-layer.md` for the underlying store.
- **main_orchestrator.py** — newer async master orchestrator. Pipeline: (1) async data fetch, (2) `run_pipeline()` (macro → options → processing → forecasting → strategy), (3) schema validation, (4) HTML report + Plotly chart, (5) JSON payload print, (6) broker execution via `_execute_broker_orders()` (only when Alpaca credentials configured). **Preflight Check (2026-07)**: Live execution runs (`dry_run=False` and `ADVISORY_ONLY=False`) require Alpaca API keys to be present; otherwise, a `PipelineFatalError` is raised to exit gracefully. New in Prompt 5.2: `main(dry_run=False)` wraps `_main_body()` in a try/finally that cancels a `_heartbeat()` asyncio background task. `_main_body()` is now a thin progress-instrumentation wrapper delegating to `_main_body_impl()` (the original cycle logic); the fatal-crash handler (`telemetry.critical(..., exc_info=True)` → `raise PipelineFatalError`) lives inside `_main_body_impl`. `_heartbeat(output_dir, interval=60)` logs `"ORCHESTRATOR ALIVE"` and writes `OUTPUT_DIR/heartbeat.txt` (UTC ISO timestamp) every 60 s so an external watchdog can detect crashes. `--dry-run` CLI flag: `python3 main_orchestrator.py --dry-run`. `_execute_broker_orders(final_df, dry_run, macro_dto)` translates BUY/SELL signals → `OrderIntent` → `OrderManager.submit_order_with_idempotency`; runs reconciliation before submission; logs CRITICAL on drift. Skipped entirely when ALPACA_API_KEY/SECRET_KEY are absent. **Persistent-daemon groundwork (2026-07):** `PipelineFatalError(RuntimeError)` is raised (never `sys.exit(1)`) on a fatal per-cycle failure (data-fetch crash, pipeline crash, or strict-mode schema-validation failure) so a long-lived caller (`desktop/daemon_runtime.py`) can catch it with a plain `except Exception`, record a FAILED run, and keep serving — the `__main__` block still converts it to `sys.exit(1)` so CI/`make verify`/the GUI subprocess see the original non-zero-exit contract. `EngineContext` (dataclass of optional pre-built engine instances: `macro_engine`, `technical_options_engine`, `iv_history_store`, `processing_engine`, `forecasting_engine`, `strategy_engine`, `evaluation_engine`) + `EngineContext.build(data_engine=...)` let a persistent caller construct every heavy engine ONCE and reuse them across cycles instead of paying full import+init cost every run; `run_pipeline(..., engines: Optional[EngineContext] = None)` and `_main_body(..., engines=..., data_engine=...)` both default to `None` (today's exact per-call construction behavior) and reuse whatever's supplied — a partially-populated context falls back to constructing only the missing engines fresh. `_main_body`'s `data_engine` param, when supplied, also bypasses the `credentials.json` check/`DataEngine`-vs-`MockDataEngine` branch entirely (the persistent caller is expected to have validated FRED configuration and built a real `DataEngine` once at startup) **Hot-path parallelization (2026-07, PR A):** the two previously-serial per-ticker loops now fan out over a `ThreadPoolExecutor` (byte-identical outputs — the loop bodies are order-independent and were already try/except-guarded): (1) the options/IV loop runs each ticker's GARCH fit + `get_30d_atm_iv` network call in `_options_one(ticker)` returning `(ticker, indicators, iv_record)`, with the `iv_store.record_iv()` writes **deferred to the main thread after the pool joins** (shared-state safety; byte-identical because `iv_engine` filters `IVHistory.date < as_of_date`, tickers are unique, and the upsert is idempotent); (2) the advisory-overlay loop runs each ticker's `evaluate(...)` in `_eval_one(...)` sized by `min(settings.ADVISORY_MAX_CONCURRENCY, 8, N)` over the shared advisory engine singletons, reassembles the results dict, and keeps the existing vectorized `.map` write-back. The blocking `run_pipeline(...)` call and the Robinhood `login()`/`fetch_positions()` calls are now wrapped in `await asyncio.to_thread(...)` so the `_heartbeat` task keeps ticking during a cycle. **Tech-bars HistoricalStore routing (2026-07):** `fetch_all_data_async()`'s tech-data task now calls `DataEngine.fetch_technical_raw_cached(...)` instead of `fetch_technical_raw(...)` (same arguments, same `asyncio.to_thread` wrapping) — closing the one remaining gap where the full async pipeline bypassed `HistoricalStore` for the entire ticker universe every cycle, unlike `main.py`'s `_fetch_bars_for_universe()` which already routed through it. `macro_task`/`fund_task` in the same function are unchanged — macro's single-snapshot freshness requirement and fundamentals' already-existing `processing_engine.py`-level DB routing are both deliberately out of scope here. **Advisory pipeline-compute reuse (2026-07, PR D, OUTPUT-CHANGING opt-in):** `_eval_one`'s `evaluate(...)` call additionally passes `precomputed_garch=_row.get('GARCH_Vol')` / `precomputed_forecast=_row.get('Forecast_30')` when `settings.ADVISORY_REUSE_PIPELINE_COMPUTE=True` (default `False`) — reusing `run_pipeline`'s already-fit values for that ticker instead of paying for a second independent GARCH + full forecast-ensemble fit inside the advisory overlay. `None`/`None` when the flag is off, reproducing the pre-dedup call exactly. See `engine/advisory.py`'s entry above for the full contract (dead-letter fallback, why `StrategyEngine.evaluate_security()` is deliberately excluded). **Robinhood account/positions caching (2026-07):** the Robinhood-integration block (building `rh_positions` for `run_pipeline(robinhood_positions=...)`) now calls `data.robinhood_portfolio.fetch_account_snapshot()` (off-threaded via `asyncio.to_thread`, matching the prior pattern) instead of a fresh, uncached `RobinhoodClient().login()` + `.fetch_positions()` every cycle — reusing the same three-tier DB→JSON→live cache `main.py` already relies on. The returned `AccountSnapshot` is converted to the `RobinhoodPositionDTO` shape `run_pipeline()` expects via the new `data.robinhood_portfolio.account_snapshot_to_robinhood_positions()` adapter. The whole block is wrapped in try/except so a live-fetch failure with no cache available degrades to `rh_positions = {}` rather than crashing the pipeline — the same dead-letter behavior the old code had on a failed `.login()`. The now-unused `from data.robinhood_client import RobinhoodClient` import is removed. **`OrderIntent.target_qty` sizing telemetry (2026-08):** `execution/broker_base.py`'s `OrderIntent` gained an optional `target_qty: Optional[float] = None` field, populated by both branches of `_execute_broker_orders`. For a BUY, `target_qty` is computed via `_kelly_target_qty(target_weight, equity, price)` where `target_weight = float(row.get("Kelly_Target_Post_Regime", kelly) or kelly)` — the pre-portfolio-cap, pre-Dual-Momentum per-name sizing decision `strategy_engine.py::evaluate_security()` writes to `Kelly_Target_Post_Regime` (Kelly cap, `MAX_POSITION_WEIGHT`, regime multiplier, meta-label composite, and the ETF-transmission multiplier already applied), which survives untouched through `pipeline/production_steps.py`'s `_SIZING_DECOMPOSITION_COLS` write-back all the way to the `ctx.dashboard_df` this function receives as `final_df` — unlike `"Kelly Target"` itself, which the Dual Momentum safe-asset override and `apply_portfolio_gross_cap()` both overwrite in place, only ever reducing it further. Falls back to `kelly` (i.e. `target_qty == qty`, today's exact prior behavior) when the column is absent (an older cached DataFrame) or falsy. Since both derating steps only ever shrink weight, `target_qty >= qty` always holds for a BUY once either has fired this cycle. For SELL/TRIM, `target_qty` is set equal to `qty` unconditionally — a full position close has no distinct target size to diverge from what's actually held. **`fetch_all_data_async()` per-task timeout (2026-08 fix)**: a real incident showed none of the three concurrent sub-fetches (`fetch_macro_raw`/`fetch_fundamentals_raw`/`fetch_technical_raw_cached`) had ANY timeout, and a stalled `fredapi.Fred.get_series()` call (bare `urlopen()`, no timeout parameter anywhere in that library) blocked the whole "data" stage — and therefore the entire pipeline cycle — for 2.5 days with nothing self-healing. Each sub-fetch is now wrapped in `asyncio.wait_for(..., timeout=settings.DATA_FETCH_TASK_TIMEOUT_SECONDS)` (default 180s); a timeout is a `TimeoutError` (`Exception` subclass) caught by the SAME existing per-task dead-letter handling already used for a raised exception — no new fallback logic needed. This alone is not a complete fix: `data_engine.py`'s FRED calls (`fetch_macro_raw_detailed`/`fetch_macro_history`) are also directly bounded via a new `_bounded_fred_timeout()` context manager (`socket.setdefaulttimeout()`, scoped and always restored) and `settings.FRED_REQUEST_TIMEOUT_SECONDS` (default 10.0), since `RunPipelineStep`/`run_pipeline()`'s own separate call into `MacroEngine.compute_hmm_risk_on_probability()` → `fetch_macro_history()` reaches the identical unbounded FRED call through a completely different, unrelated-to-this-function path. See `docs/known_issues/data_pipeline_fred_unbounded_timeout_stall.md` for the full incident. **`pipeline/runner.py::AsyncPipelineRunner.run()` structural per-step timeout (2026-08, follow-up sweep)**: this exact `await asyncio.to_thread(step.run, ctx)` dispatch was named in the original FRED incident write-up as one of two independently-unbounded paths reaching that bug, but the landed fix bounded FRED itself (`data_engine.py`), not this generic dispatcher — a future step making its own unbounded call would reproduce the identical symptom with nothing to catch it. Now wrapped in `asyncio.wait_for(..., timeout=settings.PIPELINE_STEP_TIMEOUT_SECONDS)` (default 900.0 / 15 min, well below `PIPELINE_STALL_ALERT_SECONDS`'s 1800s so this fires and lets the daemon reschedule before the stall alert would even need to trigger). A timeout propagates as a `TimeoutError` exactly like any other step exception already would — this runner deliberately never wraps steps in a blanket try/except, per its own module docstring. See `docs/known_issues/data_pipeline_fred_unbounded_timeout_stall.md`'s 2026-08-27 follow-up section. **This inner pipeline carried a second, separate unbounded hazard (2026-08-28)**: `ProcessingStep`'s per-ticker fundamentals-refresh loop (`ProcessingEngine.calculate_fundamental_metrics()` → `HistoricalStore.get_fundamentals()`), which stalled the "processing" stage for a confirmed ~1199s in a live incident — now closed via `settings.PROCESSING_FUNDAMENTALS_MAX_SECONDS_PER_CYCLE`; see that doc's 2026-08-28 follow-up section.
