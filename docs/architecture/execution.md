# Architecture: Execution (Broker, Risk Gate, Order Queue)

> Part of the split-out `CLAUDE.md` System Architecture reference. See [../../CLAUDE.md](../../CLAUDE.md) for the index.

- **execution/cost_model.py** — Tiered execution cost model and Backtrader CommissionInfo (SEC §31, FINRA TAF, tiered spreads, market order slippage).
- **execution/broker_base.py** — `BrokerBase` ABC: `OrderSide`, `OrderType`, `OrderStatus` enums; `OrderIntent`, `OrderResult`, `AccountSnapshot`, `PositionSnapshot`, `TradeUpdateEvent` dataclasses; six abstract async methods (`submit_order`, `cancel_order`, `get_open_positions`, `get_account`, `get_orders`, `stream_trade_updates`). All broker-facing strategy/orchestrator code must type-annotate against this interface.
- **execution/alpaca_broker.py** — `AlpacaBroker(BrokerBase)` using alpaca-py. Reads `settings.ALPACA_API_KEY/SECRET_KEY/PAPER`. Supports equity market/limit orders and multi-leg options via `OptionLegRequest`. Streams trade updates via `TradingStream`. Dry-run path: logs intent, returns `ACCEPTED` without touching the broker network.
- **execution/fmp_paper_broker.py** — `FMPPaperBroker(BrokerBase)` using FMP quotes and `data/paper_account_store.py` for fully-simulated, persistent paper trading with realistic slippage/fees (via `TieredCostModel`). Instant fill-or-fail synchronous fills. Supports equity market/limit orders and full multi-leg options trading (e.g. Bull Call Spreads, Bear Put Spreads, Iron Condors, Straddles, Strangles) with atomic multi-leg fills, accurate debit/credit pricing, and limit marketability checks. Selected when `settings.BROKER_BACKEND == "fmp_paper"`. Supported by `pilots/paper_broker.py` helper for the PWA endpoints (`/pilots/paper-broker/*`, `/settings/paper-broker`) backing the webapp Paper Broker screen.
- **execution/options_paper_executor.py** — `OptionsPaperExecutor`: Automated options paper execution engine. Scans quantitative options strategy directives from `technical_options_engine.py` (filtered by `passes_premium_gate` and `Integrity_OK`), enforces ticker deduplication (1 open spread per underlying), enforces `settings.MAX_CONCURRENT_OPTION_POSITIONS`, computes integer contract count via `pilots.order_sizing.calculate_multi_leg_option_sizing` capped by `settings.MAX_OPTION_NOTIONAL_PER_TRADE`, and executes atomic multi-leg fills directly into `data/paper_account_store.py`. Wired into `main.py` when `settings.PAPER_OPTIONS_AUTO_EXECUTE_ENABLED=True` and surfaced via Pilots API (`GET/POST /pilots/paper-broker/strategy-options/*`).
- **pilots/options_risk.py** — Options portfolio risk and aggregate Greeks calculation engine (`calculate_black_scholes_greeks`, `calculate_position_greeks`, `calculate_portfolio_greeks`). Computes position-level and portfolio-level net Greeks ($\Delta_{\text{net}}$, $\Delta_{\$}$, $\Gamma$, $\Theta_{\text{daily}}$, $\mathcal{V}_{\text{1\%}}$, and $\beta$-weighted $\Delta_{\text{SPY}}$) across stocks and multi-leg option positions. Surfaced via `GET /pilots/paper-broker/greeks` and rendered in the Pilots PWA Paper Broker screen. Per-symbol beta is resolved via `_resolve_symbol_beta`, returning `(beta, is_measured)`: `pilots/rolling_beta.py::rolling_beta_view` (>= 60 days of cached local price history for both the symbol and SPY) is the sole real tier; when it can't resolve, this degrades to `(1.0, False)`, logged at WARNING and surfaced per-position as `beta_is_estimated` plus a top-level `symbols_with_estimated_beta` list — never silently indistinguishable from a genuinely-measured beta of 1.0. **2026-08 fix**: a second, dead "fallback" tier previously called `data.fmp_fundamentals.compute_beta(clean)` with a single positional argument against a function requiring two `pd.Series` (`stock_returns`, `market_returns`); every call raised `TypeError`, silently swallowed. Removed rather than repaired — a correctly-fixed version (mirroring the one real working caller, `api/ws_api.py`'s `_compute_betas_sync`) would source the same `HistoricalStore` bars for the same two tickers with LESS lookback (400 days) than `rolling_beta_view`'s 504 for the same 60-observation floor, so it could never rescue a case the primary tier already failed. `calculate_portfolio_greeks` also used to resolve SPY spot as `spot_map.get("SPY") or 500.0` — a book with no direct SPY position never queried a real quote, so `beta_weighted_delta_spy` was silently computed off a fabricated $500 (CONSTRAINT #4 violation). Fixed: SPY is now added to the same `distinct_tickers` set resolved via `market_provider.get_latest_quote()` as every other symbol; when genuinely unresolvable, `beta_weighted_delta_spy` reports `0.0` (never a fabricated-price computation) and the new `spy_spot`/`spy_spot_resolved` response fields let a caller detect the difference from a real flat book. See [`docs/known_issues/options_risk_fabricated_spy_spot.md`](../known_issues/options_risk_fabricated_spy_spot.md) for the confirmed live-trading-path impact and evidence.
- **pilots/options_hedging.py** — Dynamic delta hedging and rebalancing engine (`calculate_delta_hedge_order`, `get_delta_hedge_preview`, `execute_delta_hedge`). Computes SPY share requirements to neutralize $\beta$-weighted delta with deadband filtering (`settings.OPTIONS_DELTA_HEDGE_BAND_SPY_SHARES`). Surfaced via `GET/POST /pilots/paper-broker/delta-hedge/*`. `pilots/paper_broker.py::get_portfolio_greeks()` and `main.py`'s automated hedge cycle (`_run_automated_delta_hedge_cycle`, gated by `settings.OPTIONS_DELTA_HEDGE_ENABLED`) both now pre-resolve ONE real SPY quote via `pilots.price_provider.get_current_price` and thread the identical value into both `calculate_portfolio_greeks` (sizing) and `execute_delta_hedge` (fill) — previously the automated cycle called `calculate_portfolio_greeks(store=...)` with no `spy_spot` at all (fabricating $500 internally, see the `pilots/options_risk.py` entry above) while `execute_delta_hedge` separately resolved and filled at the REAL SPY price, so a live (paper) hedge order's share quantity could be sized off a fabricated price while it filled at a different, real one. The cycle now fails closed (skips entirely, logs a WARNING) rather than sizing a hedge off a guess when no live SPY quote is available. A second, adjacent bug fixed in the same pass: the automated cycle's post-hedge success log read `_hedge_res.get("executed")`/`_hedge_res.get("spot_price")`, keys `execute_delta_hedge`'s real return contract never had (it uses `"hedged"` and nests the fill price at `fill["fill_price"]`) — so that INFO log had never once printed. See [`docs/known_issues/options_risk_fabricated_spy_spot.md`](../known_issues/options_risk_fabricated_spy_spot.md).
- **pilots/volatility_surface.py** — Volatility surface, IV smile spline interpolation, term structure, 25-delta Put-Call skew, and Volatility Risk Premium (VRP) cone engine (`calculate_volatility_surface`). Surfaced via `GET /pilots/options/vol-surface` and rendered in `VolSurfaceView.tsx`.
- **pilots/scenario_matrix.py** — Multi-dimensional scenario stress grid and historical shock engine (`evaluate_scenario_matrix`, `evaluate_single_scenario`, `evaluate_historical_presets`, `get_2d_scenario_slice`). Shocks underlying spots, implied volatilities, and forward calendar time horizons across positions with 1e-12 degenerate guard and 0DTE intrinsic fallback. Evaluates historical stress presets (Lehman 2008, Volmageddon 2018, COVID 2020, Yen Unwind 2024). Surfaced via `POST /pilots/paper-broker/scenario-matrix` and rendered in the Pilots PWA Scenario Heatmap component.
- **pilots/earnings_crush.py** — Earnings volatility crush analytics and trade construction engine (`calculate_expected_earnings_move`, `get_historical_earnings_moves`, `evaluate_earnings_crush_candidates`). Computes ATM straddle expected moves ($0.80 \times S \times \sigma_{\text{ATM}} \times \sqrt{\text{DTE}/365}$), extracts past 8 quarters of post-earnings percentage gaps from `HistoricalStore.get_earnings_events()`, and calculates Crush Edge Ratio ($\text{Implied} / \text{Median Realized}$). Constructs delta-neutral Iron Condors when Edge $\ge 1.25\times$. Surfaced via `GET /pilots/options/earnings-crush/candidates` and executed via `POST /pilots/options/earnings-crush/execute`.
- **pilots/unusual_options_flow.py** — Real-time options order flow anomaly and institutional sentiment engine (`scan_unusual_options_activity`, `calculate_net_flow_sentiment`). Detects volume spikes ($V / \text{OI} \ge 3.0$, notional $\ge \$100\text{k}$), categorizes trade aggressors (Aggressive Ask Sweeps vs Passive Bid Blocks), flags IV expansion anomalies ($\text{IV} \ge 1.25 \times \text{HV}_{30}$), and aggregates net institutional flow sentiment score $\in [-1.0, +1.0]$. Surfaced via `GET /pilots/options/flow/*` and fed into `signals/options_flow_sentiment.py`. `get_unusual_options_activity()` is a read-through cache: it serves persisted `output/unusual_options_flow.json` records first, and on a miss (and only for a caller-supplied, bounded `symbols` list — never an unfiltered universe-wide scan inside one request) fetches a real chain per symbol via `data/market_data.py`'s `CompositeOptionsProvider`/`CompositeProvider` (the same lazy-import pattern `pilots/options_gex.py`/`pilots/vol_mispricing.py`/`pilots/har_volatility.py` use), scans it, and persists the findings via `save_uoa_records()` (trimmed to `MAX_PERSISTED_UOA_RECORDS`=2000, newest-first) — closing a 2026-08 production gap where the endpoint's only caller passed a hardcoded empty chain and nothing ever called `save_uoa_records()`, making `/pilots/options/flow/unusual` structurally inert. Never fabricates a record or falls back to a synthetic chain (CONSTRAINT #4) — an unfiltered request with nothing persisted yet, or a provider miss, honestly returns `[]`.
- **pilots/options_alerts.py** — Multi-channel real-time alert dispatcher for the options desk (`dispatch_uoa_whale_alert`, `dispatch_earnings_crush_alert`, `dispatch_delta_hedge_alert`, `dispatch_options_alert`/`format_options_alert_message`, `post_webhook`). Formats and fans out institutional UOA whale sweeps (Vol/OI $\ge 5.0$, notional $\ge \$250\text{k}$), high-edge pre-earnings volatility-crush candidates (Crush Edge $\ge 1.35\times$), and portfolio delta-hedge-imbalance alerts through `observability/alerts.py`'s multi-channel dispatcher (console/file/Discord/Slack/email) plus an optional dedicated `settings.OPTIONS_ALERT_WEBHOOK_URL` POST. Dedup keys passed to `send_alert(..., dedup_key=...)` are condition-scoped per `settings.ALERT_DEDUP_WINDOW_SECONDS` (default 900s); the UOA whale key includes `sentiment` so a genuinely new, opposite-direction sweep on the same contract within the window is never wrongly suppressed as a duplicate of an earlier alert in the other direction, while same-direction repeats still correctly dedupe. A webhook POST failure is always logged at WARNING and returned in the response (`webhook_status`/`webhook_error`), never silently swallowed. Actively wired into live evaluation paths: `pilots/unusual_options_flow.py` triggers `dispatch_uoa_whale_alert`, `pilots/earnings_crush.py` triggers `dispatch_earnings_crush_alert`, and `pilots/options_hedging.py` triggers `dispatch_delta_hedge_alert` from BOTH `get_delta_hedge_preview()` and `execute_delta_hedge()` (the latter is the path `main.py`'s unattended automated pipeline cycle actually reaches). **2026-08 follow-up fix**: the PR that first wired these three call sites shipped two real bugs, since fixed — (1) `earnings_crush.py`'s dispatch condition was `is_recommended or crush_edge_ratio >= 1.35`, which could alert on synthetic/fallback-data candidates despite `is_recommended` deliberately excluding them (CONSTRAINT #4); now gated on `is_recommended` alone. (2) `execute_delta_hedge()`'s dispatch call passed the raw `order` dict (from `calculate_delta_hedge_order`: `side`/`qty`/`shares_needed`), which lacks the `action`/`required_action`/`shares` keys `dispatch_delta_hedge_alert`'s qualifying gate reads — every call there silently evaluated to `dispatched=False`, so this dispatcher never actually fired from the one place it's meant to run unattended. Both fixes have targeted regression tests (`tests/test_earnings_crush.py`, `tests/test_options_hedging.py`) asserting the dispatcher mock is/isn't called under the qualifying/non-qualifying condition. Also surfaced via `POST /pilots/options/alerts/test`.
- **pilots/har_volatility.py** — Corsi (2009) Heterogeneous Autoregressive Realized Volatility model (`compute_realized_variance_components`, `fit_har_rv_model`, `forecast_forward_volatility`). Decomposes variance into daily, weekly, and monthly horizons with non-negativity constrained OLS regression, projecting forward term-structure fair implied volatility. Surfaced via `GET /pilots/options/forecast/har-rv`.
- **pilots/vol_mispricing.py** — Strike-by-strike volatility mispricing and fair value scanner (`evaluate_strike_mispricing`). Computes $IV_{\text{market}} - IV_{\text{fair}}$ spread, classifies Rich ($\ge +3.0\%$ vol points, recommending Credit Spreads / Iron Condors) vs Cheap ($\le -3.0\%$ vol points, recommending Debit Spreads / Long Straddles / Convexity) strikes. Surfaced via `GET /pilots/options/forecast/mispricing` and rendered in `VolForecastScanner.tsx`.
- **pilots/gamma_scalper.py** — Intraday discrete gamma scalping simulator and Greek attribution engine (`simulate_gamma_scalping`). Simulates threshold delta hedging ($|\Delta| \ge 0.15$) along price paths, decomposing returns into Realized Gamma Rent $\frac{1}{2}\sum \Gamma (\Delta S)^2$ vs Theta Time Decay $\sum \Theta \Delta t$ vs execution friction. Surfaced via `POST /pilots/options/gamma-scalp/simulate` and rendered in `GammaScalperView.tsx`.
- **pilots/dispersion_trading.py** — Cross-asset options dispersion and implied correlation arbitrage engine (`compute_implied_correlation`, `compute_realized_correlation_matrix`, `evaluate_dispersion_opportunity`, `build_dispersion_basket`, `execute_dispersion_trade`). Computes Driessen/Maenhout/Vilkov (2009) implied index correlation $\bar{\rho}_{\text{implied}}$, calculates correlation spread $\Delta\rho = \bar{\rho}_{\text{implied}} - \bar{\rho}_{\text{realized}}$, and constructs vega-neutral index vs constituent baskets (e.g. Short QQQ Straddle + Long 8 tech component straddles). Surfaced via `GET/POST /pilots/options/dispersion/*` and rendered in `DispersionScanner.tsx`.
- **pilots/zero_dte_engine.py** — 0DTE intraday momentum and volatility breakout desk (`compute_opening_range`, `detect_volatility_squeeze`, `scan_0dte_breakouts`, `get_0dte_signals`, `evaluate_0dte_exits`, `execute_0dte_trade`, `execute_0dte_exits`). Computes the 9:30–9:45 ET opening range ($[\text{Low}_{15}, \text{High}_{15}]$), detects directional breakout thrust plus a TTM volatility squeeze (Bollinger-in-Keltner) gate, and selects a high-gamma ATM/1-OTM contract (delta $\approx 0.40$–$0.55$) expiring same-session. Fast risk lifecycle: `settings.OPTIONS_0DTE_PROFIT_TARGET_PCT` (default +75%), `settings.OPTIONS_0DTE_STOP_LOSS_PCT` (default -30%), and a mandatory `settings.OPTIONS_0DTE_HARD_EXIT_TIME` (default 15:45 ET) hard time-stop to eliminate closing-assignment/pin risk. Gated end-to-end by `settings.OPTIONS_0DTE_ENABLED` (default `False`). Surfaced via `GET /pilots/options/zero-dte/signals` and `POST /pilots/options/zero-dte/execute`.
- **pilots/options_vpin.py** — Volume-Synchronized Probability of Toxicity (VPIN) microstructure risk engine (`compute_vpin_buckets`, `calculate_vpin`, `evaluate_toxicity_regime`, `apply_defensive_spread_concession`). Implements Easley/López de Prado/O'Hara (2012) VPIN with Bulk Volume Classification (BVC). Detects informed toxic flow ($VPIN > 0.35$) and applies defensive limit price adjustments. Surfaced via `GET /pilots/options/vpin/metrics` and rendered in `VpinGauge.tsx`. Toxicity gate is operator-tunable via `settings.OPTIONS_VPIN_TOXICITY_THRESHOLD` (default 0.35, promoted from the module's prior hardcoded `DEFAULT_TOXICITY_THRESHOLD`). **Live-data fix (2026-08-22)**: `get_options_vpin_metrics()` (the function backing the live endpoint) used to call `generate_synthetic_option_trades()` UNCONDITIONALLY — a random-walk generator whose own docstring says "for testing and simulation" — so the live, non-mock endpoint always returned a VPIN computed from fabricated data, with no indication anywhere that it wasn't real. There is no real per-trade options tick stream anywhere in this codebase (`pilots/unusual_options_flow.py` only has point-in-time chain snapshots; no configured market-data provider exposes one), so a genuinely tick-resolution VPIN is not available. Fixed (CONSTRAINT #4) by having `get_options_vpin_metrics()` fetch REAL hourly OHLCV bars for the underlying via a new `fetch_real_underlying_bar_trades()` (`data.market_data.get_provider().get_intraday_bars(..., interval="1h")`) and compute a coarse, bar-level BVC approximation from them — the identical honest pattern already used by `desktop/daemon_runtime.py::maybe_update_circuit_breaker`'s own VPIN sub-step (see that entry below). When real bars cannot be fetched (provider failure, empty/malformed payload, too little history), the response degrades to an explicit `data_available: False` / `vpin: None` / `reason: "..."` payload instead of silently substituting synthetic data; `VpinGauge.tsx` renders this as an honest "UNAVAILABLE" state (no gauge reading, no regime badge) rather than falling back to a plausible-looking default. On success, the response carries `data_available: True` and `data_source: "bar_level_bvc_approximation"` so no caller can mistake this for tick-level toxicity. `generate_synthetic_option_trades()` itself is unchanged and remains legitimately used by `tests/test_options_vpin.py`'s pure-math unit tests. See `docs/known_issues/options_vpin_fabricated_live_data.md` for the full write-up.
- **pilots/options_sor.py** — Multi-leg options Smart Order Router (SOR) and legging optimization simulator (`analyze_routing_options`, `simulate_legging_execution`). Compares direct Complex Order Book (`COB_NET_PACKAGE`) execution vs. synthetic leg-by-leg routing (`LEG_PASSIVE_FIRST` vs `SPLIT_DIRECT`), modeling inter-leg latency drift, hung-leg hazard risk, and Monte Carlo execution shortfall. Surfaced via `POST /pilots/options/sor/*` and rendered in `SmartOrderRouterView.tsx`. Assumed inter-leg execution latency is operator-tunable via `settings.OPTIONS_SOR_LEGGING_LATENCY_SECONDS` (default 2.0s, promoted from `simulate_legging_execution`'s prior hardcoded default).
- **pilots/lob_simulator.py** — Cont, Stoikov, Talreja (2010) Level-3 Limit Order Book (LOB) Markovian queue position simulator and liquidity slicing engine (`compute_lob_arrival_rates`, `simulate_queue_position`, `evaluate_optimal_queue_level`, `slice_liquidity_order`). Models Poisson arrival rates ($\lambda, \mu, \theta$) and simulates queue priority progression, fill probability curves, and fill latency percentiles. Surfaced via `POST /pilots/options/lob/simulate-queue` and rendered in `LobDepthView.tsx`. Default/fallback market-order arrival rate $\theta$ is operator-tunable via `settings.OPTIONS_LOB_DEFAULT_MARKET_ORDER_RATE` (default 5.0 orders/sec, promoted from the module's prior hardcoded `DEFAULT_MARKET_ORDER_RATE`).
- **pilots/options_gex.py** — Options Gamma Exposure (GEX) and market maker dealer hedging engine (`calculate_option_gex_profile`, `calculate_zero_gamma_flip`, `classify_gamma_regime`). Computes strike-by-strike Call vs Put GEX, locates Call Gamma Walls (resistance), Put Gamma Walls (support), and Zero-Gamma Flip Point ($S^*$). Classifies volatility regimes (`POSITIVE_GAMMA` volatility dampener vs `NEGATIVE_GAMMA` volatility accelerator) and pin risk concentration. Surfaced via `GET /pilots/options/gex/profile` and rendered in `GexProfileView.tsx`. The Zero-Gamma Flip Point's Brent's-method search radius is operator-tunable via `settings.OPTIONS_GEX_SEARCH_RANGE_PCT` (default 0.20 = ±20% of spot).
- **pilots/copula_stat_arb.py** — Cross-asset statistical arbitrage and non-linear vine copula engine (`fit_bivariate_copula`, `select_best_copula`, `estimate_kalman_dynamic_hedge_ratio`, `compute_copula_spread_and_zscore`, `generate_copula_stat_arb_signals`). Fits Clayton ($\lambda_L = 2^{-1/\theta}$), Gumbel ($\lambda_U = 2 - 2^{1/\theta}$), Frank, and Gaussian copulas to evaluate joint tail risk, tracks dynamic hedge ratios $\beta_t$ via state-space Kalman filtering, and estimates Ornstein-Uhlenbeck half-life $\tau_{1/2}$ for mean-reversion spread execution. Surfaced via `GET /pilots/options/copula/pairs` and rendered in `CopulaSpreadView.tsx`. The mean-reversion spread entry/exit z-score band is operator-tunable via `settings.OPTIONS_COPULA_ZSCORE_ENTRY_THRESHOLD` (default 2.0, promoted from the module's prior hardcoded literal). **Lookahead-bias fix history**: a 2026-08 PR made `evaluate_copula_stat_arb_pair`'s spread computation and `generate_copula_stat_arb_signals`' per-bar copula tail-dependence check strictly causal (each uses only data available at/before timestep `t`), but the causal per-bar gate it introduced silently dropped the OU half-life mean-reversion criterion for every bar except the last — the original (non-causal) `tail_risk_acceptable` gate had always checked both tail-dependence AND half-life together. A 2026-08 follow-up restored the half-life half of the per-bar gate causally (a rolling AR(1) OU-half-life estimate on the same trailing window used for the copula refit, gated to `[half_life_min, half_life_max]`), so `step_tail_ok` again requires both criteria on every bar, not tail-dependence alone. Regression-tested in `tests/test_copula_stat_arb.py::test_generate_copula_stat_arb_signals_requires_causal_half_life_not_only_copula` (monkeypatches both checks independently to prove the gate is a genuine AND, not a pass-through).
- **ml/drl_market_maker.py** — Avellaneda-Stoikov (2008) closed-form quoting engine and deep reinforcement learning market making environment (`compute_reservation_price`, `compute_optimal_spreads`, `MarketMakingEnv`, `simulate_market_maker_execution`, `train_market_maker_policy`). Solves high-frequency optimal quoting with Poisson fill dynamics, dynamic inventory risk penalization, and PnL attribution. Surfaced via `POST /pilots/options/market-maker/simulate` and rendered in `MarketMakerAgentView.tsx`. The absolute risk-aversion parameter $\gamma$ driving inventory-skew strength in the reservation price is operator-tunable via `settings.OPTIONS_DRL_RISK_AVERSION_GAMMA` (default 0.10, promoted from the module's prior hardcoded `DEFAULT_GAMMA`).
- **data/paper_account_store.py** — SQLite store tracking virtual cash balance (`settings.FMP_PAPER_STARTING_CASH`), open positions (long equities, long options, and short options `qty < 0`), and order ledger for `FMPPaperBroker`. Performs atomic multi-leg transactions (`apply_multi_leg_fill`, `apply_roll_fill`) and dynamic mark-to-market option valuation via Black-Scholes using underlying spot quotes. Single-operator schema (`PaperAccount.id` is always `1`, no user/account dimension).

- **execution/dynamic_circuit_breaker.py** — Dynamic intraday circuit breaker engine and flash liquidity guardrail (`DynamicCircuitBreaker`, `CircuitBreakerState`, `CircuitBreakerMetrics`). Defines three sub-checks: (1) Volatility Jump Detector (5m EWMA realized vol $Z_\sigma > 3.5 \implies$ `SOFT_HALT` via `VOLATILITY_BURST_HALT`); (2) Flash Crash Shield ($\text{OFI} < -\text{threshold} \land \text{VPIN} > 0.40 \implies$ `SOFT_HALT` via `FLASH_CRASH_SHIELD`); (3) Intraday Loss Velocity Brake ($d(\text{PnL})/dt \le -(\text{Daily Loss Limit}/30\text{m}) \implies$ `HARD_HALT` via `LOSS_VELOCITY_BREACH`). **Real current wiring status (Phase 31-36 remediation, 2026-08), stated plainly rather than implying full automation**: only the Volatility Jump Detector has an automatic live data feed — gated by `settings.CIRCUIT_BREAKER_ENABLED` (default `False`), `desktop/daemon_runtime.py`'s `OrchestratorDaemon.maybe_update_circuit_breaker()` runs on every `_timer_loop` wake, builds a rolling 20-day vol baseline from `settings.CIRCUIT_BREAKER_REFERENCE_SYMBOL` (default `SPY`) daily bars plus a reactive recent-hourly window, and persists the resulting Z-score via `update_metrics(persist=True)`. The Flash Crash Shield (OFI/VPIN) and Loss Velocity Brake remain **manual-only** — no live equity order-flow or intraday PnL time-series data source exists anywhere in this codebase to feed them automatically; an operator trips either directly via `python -m execution.kill_switch --activate-soft-halt`/`--activate`. `PreTradeRiskGate.dynamic_circuit_breaker_check`'s file-sentinel fallback (`execution/risk_gate.py`, used whenever no `DynamicCircuitBreaker` instance is injected via context) fails SAFE to `SOFT_HALT` on any evaluation exception (previously failed open, silently passing orders through) and checks both `HARD_HALT` and `SOFT_HALT` from `GlobalKillSwitch` plus whatever the live updater persisted via `load_metrics()`, taking the more severe of the two. Evaluates order intents via asymmetric gating (blocks risk-increasing BUY orders under `SOFT_HALT` while permitting risk-reducing SELL orders; blocks all orders under `HARD_HALT`). Persists atomic state to `output/circuit_breaker_state.json`. Surfaced via `GET /risk/circuit-breaker/status` on `api/data_api.py` and rendered in `DynamicCircuitBreakerBadge.tsx`.
- **execution/kill_switch.py** — File-based global kill switch. `KILL_SWITCH_FILE = settings.OUTPUT_DIR / "KILL_SWITCH"` and `SOFT_HALT_FILE = settings.OUTPUT_DIR / "SOFT_HALT"` are the sentinels. `GlobalKillSwitch.is_active()` checks file presence; `activate(reason)` writes atomically (write-then-rename); `deactivate()` removes the file. `is_soft_halt_active()` and `activate_soft_halt(reason)` provide asymmetric soft halt coordination. `KillSwitchActiveError(RuntimeError)` is raised by `OrderManager.submit_order_with_idempotency` BEFORE any pre-trade check when the kill-switch file exists. CLI: `python -m execution.kill_switch --activate/--deactivate/--activate-soft-halt/--deactivate-soft-halt/--status`. `FLATTEN_ON_KILL=true` logs a CRITICAL reminder (automatic flattening is a future extension).
- **execution/risk_gate.py** — Synchronous eleven-check pre-trade risk pipeline. `RiskContext` dataclass holds per-call live state (account, open_positions, macro DTO, returns_df, start_of_day_equity, validation_reports, is_premium_sell_strategy, current_prices, timestamp, circuit_breaker_state, circuit_breaker_metrics). `PreTradeRiskGate.run_all(intent, context)` short-circuits at the first failure; the eleventh check (`max_order_rate_check`) is always last so blocked orders never consume rate-limit budget. Checks in order: (0) dynamic_circuit_breaker_check, (1) max_position_size, (2) portfolio_heat, (3) max_correlation, (4) daily_loss_limit, (5) macro_kill_switch, (6) hmm_regime, (7) stress_scenario, (8) market_hours (NYSE RTH 09:30–16:00 ET via `zoneinfo`), (9) minimum_validation, (10) max_order_rate. Missing context → conservative pass (never blocks on missing data). Thresholds injectable at construction; default to `settings.*` counterparts.
- **execution/order_manager.py** — `OrderManager` sitting between the signal pipeline and the broker adapter. - **execution/compose.py** — **cross-Pilot + advisory execution-queue COMPOSER — the single writer of `output/execution_queue.json`.** Two writers previously shared that one file (`main.py`'s advisory cycle, every cycle; `pilots/mirror.py::plan_follow`, request-driven) with no coordination — whichever ran last silently overwrote the other (latent only because the default `ROBINHOOD_EXECUTION_MODE="off"` makes the follow path write nothing). Now every source (advisory, and each actively-followed Pilot) writes its own small JSON file to `output/queue_sources/<source_id>.json` (`{schema_version, source_id, generated_at, targets, dropped_targets}`, atomic write-then-rename) — `write_advisory_source(recommendations)` (raw, unfiltered actionable BUY/SELL recs; conviction filtering happens at COMPOSE time against the live `queue_builder.CONFIG["min_conviction"]`, not write time) and `write_follow_source(pilot, amount, snapshot, prior_mirrored=...)` (`pilots.mirror.build_follow_targets`'s pure current targets, plus any `prior_mirrored` row whose symbol just dropped out — a just-detected drop this follow may still need to force-exit). `compose_and_emit(account_snapshot, ...)` reads every source, calls `compose_targets`, and hands the result to the UNCHANGED `execution.queue_builder.emit_execution_queue` as a `FollowRunResult`-shaped `_ComposedRunResult` — zero `queue_builder.py` changes beyond the `strategy_id`/`sources`/`overridden` additions documented above. **Composition rules**, per symbol: (1) **advisory always wins outright** when present (BUY or SELL, above the conviction gate) — its own recommendation is emitted byte-identical to advisory-alone, any follow claim on that symbol is recorded in the emitted intent's `overridden` field (never netted in) — a deliberate, conservative product decision (confirmed with the operator) since summing an independent risk signal with a preference risks stacking into an oversized position; (2) absent an advisory claim, **follow sources are netted by summing TARGETS, never already-netted deltas** — two Pilots wanting $3750/$2000 of a symbol nets to one correctly-sized trim against actual current holdings, computed exactly once; summing each Pilot's own already-netted delta double-subtracts the same holding (verified in `tests/test_compose.py::TestMoneyTestNetTargetsNotDeltas` against numbers where the sum-of-deltas answer isn't even a valid sell size); (3) the no-trade band scales with the NET target (`max($1, 5% × net_target)`) so a 5% band never suppresses a genuine full drop (`net_target=0` → band=$1 exactly); (4) **force-exit under the union is capped by `source_claim`** — the sum, across every follow source, of whichever of its current-target or dropped-target row exists for that symbol — which is what stops a follow's force-exit from selling the operator's own non-follow-attributed shares in the same name. **Dead-letter posture is asymmetric by design:** a MISSING source (a Pilot never explicitly followed via `plan_follow` yet) is legitimate and excluded from the union, composition proceeds; a CORRUPT (unparseable) or STALE (`generated_at` older than `settings.QUEUE_SOURCE_MAX_AGE_SECONDS`, default 7 days — a documented judgment call, not a derived constant) source instead refuses the ENTIRE compose call (writes nothing, leaves the previously-emitted queue in place) rather than silently composing on a subset of trustworthy data — CONSTRAINT #6 ("don't crash") is not the same promise as "proceed with best-effort partial data," and for order-adjacent code silently proceeding on wrong data is the worse failure mode. `pilots/mirror.py::build_follow_intents` is now a thin single-source wrapper over this module's `compose_targets` (verified byte-identical against all 41 pre-existing tests in `tests/test_pilots_mirror.py`, unchanged — the safety net the whole refactor leans on). Lives inside the sanctioned `execution/` order-code zone; added to `tests/test_pipeline_smoke.py::TestNoOrderFunctions`'s manual `_EXECUTION_ZONE_GUARDED_FILES` scan-target list (a new `execution/` file is unscanned by either guard until added there — see that test's own docstring). Never contacts a broker; defines no order-submission function. **New setting:** `settings.QUEUE_SOURCE_MAX_AGE_SECONDS` (float, default 604800.0 = 7 days). **Real macro context wiring (2026-08 fix):** `compose_and_emit` accepts an optional `macro_dto` (`main.py` passes `result.macro_dto`), threaded into `_ComposedRunResult` and forwarded to `emit_execution_queue`. ## Future extension point — automated Robinhood execution (not implemented)

`settings.BROKER_BACKEND` is reserved to eventually accept `"robinhood"` as a third value alongside `"alpaca"`/`"fmp_paper"`. Today, any value other than `"fmp_paper"` falls through to `AlpacaBroker` via the existing `else` branch in `main_orchestrator.py::_execute_broker_orders` and `broker_live_execution_mcp.py`'s broker-construction helper — so this is a **documentation reservation only, zero behavior change** until a `RobinhoodBroker` class actually exists and is wired into that branch. A future `RobinhoodBroker(BrokerBase)` would need to implement the same six abstract async methods `AlpacaBroker`/`FMPPaperBroker` already implement — `submit_order`, `cancel_order`, `get_open_positions`, `get_account`, `get_orders`, `stream_trade_updates` (see `execution/broker_base.py`'s `BrokerBase` class) — using those two classes as the implementation template, and would plug into `main_orchestrator.py`'s fully-automated pathway (A) above exactly like they do. This is genuinely new, unstarted work, not a small wrapper: it requires real `robin_stocks` order-submission code that does not exist anywhere in this codebase today — every existing `data/robinhood_*.py` module (`robinhood_login.py`, `robinhood_session.py`, `robinhood_client.py`, `robinhood_portfolio.py`) is read-only (account/portfolio snapshots and login), never order placement. Building this would also mean deciding how it coexists with pathway (B)'s human-confirmed queue+skill bridge above, which remains the only sanctioned way to place a real Robinhood order until this extension point is built out.
